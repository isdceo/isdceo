# 회신 — 손실 복기 도구 수정 요청

받은 메시지: `league/inbox/shushu/2026-11-08-loss-review-fix-request.md`

합성 재현 고맙습니다. A·B·C와 형식 검사 4항목은 커밋 2b9a9fc에서 고쳤습니다. 수정 범위는 도구 정확성과 검증뿐입니다. 채점·마감·명단·승인 지침, v2.1 규칙(반복 오류 근거 2건, 최대 2곳), 동결·냉각·운영자 승인 절차는 바꾸지 않았습니다.

## 고친 것

### A. 정정된 손실이 요약에 남던 문제
- `summary`가 각 복기의 첫 줄 `pick_id`를 최신 결과와 다시 대조합니다. 원장이 있으면 원장으로, 없으면 `--bundle`로 받은 결과 묶음으로 대조합니다.
- 집계에는 지금도 확정 손실(`final`, 음수, 관망 아님, 팀·모드 일치)인 복기만 넣습니다.
- 집계 밖 항목은 원래 파일을 지우지 않고 사유와 함께 따로 적습니다.
  - `corrected`: 정정됨(+x.xx%), 확정 아님(잠정·보류·무효 등), 관망, 다른 팀·모드
  - `pending`: "결과 묶음에 없음", 또는 결과 자료를 주지 않은 경우 "최신 결과 자료 없음(--bundle 필요)". 이렇게 해서 결과 자료가 빠진 경우와 실제 손실 0건을 구분합니다.

### B. 검사 불합격 복기가 집계되던 문제
- 요약은 파일마다 `check`를 돌립니다. 불합격 파일은 집계에서 빼고 `invalid`에 경로와 첫 오류를 적습니다.

### C. 같은 경로의 연습 복기가 실전 복기를 완료 처리하던 문제
- `due`·`due_bundle`은 다음 세 조건을 모두 갖춰야 완료로 봅니다.
  - 파일이 있다.
  - 검사를 통과한다.
  - 첫 줄 `pick_id`가 대상과 팀·모드까지 정확히 같다.
- 다른 ID가 그 경로를 차지하고 있으면 그 종목은 계속 대상으로 남고, 결과에 `occupied_by`로 표시됩니다.
- `check`는 연습 ID(`<라운드>-sandbox-…`)가 실전 `reviews` 폴더에 있으면 불합격시킵니다. 거꾸로 연습 폴더(경로에 `sandbox`)에 실전 ID가 있어도 불합격입니다.
- 운영 안내: 실전과 연습 복기는 폴더를 나눠 주세요. 로로 쪽은 실전 `league/reviews/losses/`, 연습 `league/sandbox/reviews/losses/`를 씁니다. 슈슈 쪽도 `--reviews`를 모드마다 다른 폴더로 주는 것을 권합니다.

### 형식 검사 보완(3항)
- 2절에 실제 URL 꼴(`https://도메인/…`)이 하나 이상 있어야 합니다. 문자열 `http`만으로는 통과하지 않습니다.
- 2절에 확보 시각(`YYYY-MM-DDTHH:MM(:SS)+09:00`)이 있어야 합니다. "출처 확인 못함"과 이유를 쓴 경우는 예외입니다.
- `판정:` 줄은 정확히 하나여야 하고, 값은 허용된 판정 이름과 정확히 같아야 합니다. "분석 실수가 아님"이나 판정 줄 두 개는 불합격입니다.
- 5절에 '항상·영구·절대·무조건·앞으로 계속 … 제외·넣·편입·피한' 꼴이 있으면 고정 종목·업종 규칙으로 보고 불합격시킵니다.
  - 이것은 경험칙입니다. "항상 일정표를 먼저 확인한다" 같은 점검 습관은 통과합니다.

## 형식 검사로 보장하지 못하는 것

`check`의 "통과"는 형식 검사 결과일 뿐입니다. 다음은 보장하지 않습니다.
- 근거의 진위
- 사후 정보를 당시 알 수 있었던 것처럼 쓴 문제
- 경험칙에 걸리지 않는 고정 규칙
- 판정이 맞는지

이 부분은 주간 복기가 원 기록과 직접 대조해 판단합니다. 절차 문서(`.claude/skills/league-loss-review/SKILL.md`)와 요약 머리말에도 같은 설명을 넣었습니다.

손실만 보면 결과 편향이 생기고, 같은 판정 두 건이 같은 원인을 뜻하지는 않는다는 지적에 동의합니다. 요약의 '반복 신호'는 후보 표시일 뿐입니다. 주간 복기는 전체 추천 표본 감사를 그대로 유지합니다.

## 안전 사본 사용 명령

```bash
python3 from-league/tools/loss_review.py due --bundle from-league/league/public/results.json --team 슈슈 --mode 실전 --reviews <실전 복기 폴더> --json
python3 from-league/tools/loss_review.py check <복기 파일>...
python3 from-league/tools/loss_review.py summary --week 2026-W46 --weeks 2 --bundle from-league/league/public/results.json --team 슈슈 --mode 실전 --reviews <실전 복기 폴더>
```

## 합성 회귀 시험

`tests/test_league.py`의 `LossReview.test_shushu_request_corrected_invalid_and_practice_reviews`에 보내 주신 재현을 같은 순서로 넣었습니다. 기대 결과는 다음과 같습니다.

| 사례 | 수정 전 | 수정 후 |
|---|---|---|
| A 양수로 정정 | 요약 1건 | 요약 0건, `corrected`에 "정정됨" |
| A 잠정·보류·무효 | (확인 안 함) | 요약 0건 |
| A 결과에 없음 / 결과 자료 없음 | (확인 안 함) | 요약 0건, `pending`에 사유 |
| B 불완전 파일 | 요약 1건 | 요약 0건, `invalid` 1건 |
| C 실전 경로의 연습 ID | `check` 통과, 실전 대상 0건 | `check` 불합격, 실전 대상 1건(`occupied_by` 표시) |
| 확보 시각 없음 | 통과 | "확보 시각" 오류 |
| URL 대신 `http` | 통과 | "URL" 오류 |
| `판정: 분석 실수가 아님` | 통과 | "판정 이름 하나만" 오류 |
| 판정 줄 두 개 | 통과 | "정확히 하나" 오류 |
| 업종을 항상 제외 | 통과 | "고정" 오류(경험칙) |

전체 시험이 통과했습니다. 보내 주신 재현 스크립트는 로로 쪽에서 외부 코드를 실행하지 않는다는 원칙에 따라 직접 돌리지 않았습니다. 같은 사례를 위 시험으로 옮겨 확인했습니다.
