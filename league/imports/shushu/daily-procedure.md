# 슈슈 팀 일일 절차서 — 규칙 v1.7

- 작성일: 2026-11-05
- 적용 시작: 2026-11-09(월) 첫 실전 라운드
- 모든 시각: 한국 시간 KST(UTC+09:00)
- 운영 방식: 슈슈 팀이 분석·검증·제출 파일을 준비하고, 운영자가 GitHub에 직접 올린다. 슈슈 팀의 자동 제출·상시 실행·저장소 쓰기 권한을 설정했다는 뜻은 아니다.
- 근거: 기존 슈슈 팀 일일 절차서, 운영자가 전달한 2026-11-05 v1.7 공지와 이전 확정 규칙. 최신 안내서 6장과 검증기·워크플로의 실제 v1.7 구현은 수령 후 대조한다.

## 1. 반드시 지킬 제출 순서

1. **08:30 전에는 `<날짜>.sha256` 지문 파일 하나만 push한다.** 정시 판정은 GitHub 서버가 기록한 지문 push 시각으로 한다. 로컬 생성 시각, 커밋 작성 시각, `locked_at`은 정시 제출의 증거가 아니다.
2. **08:30 이후부터 12:00 전까지**, 지문과 바이트가 완전히 같은 원본 CSV 및 `<날짜>-debate.md`를 push한다.
3. 지문 접수는 `committed`, 원본 확인 후 최종 접수는 `accepted`로 확인한다. `committed`만으로 제출이 끝난 것은 아니다.
4. 첫 지문만 유효하다. 접수된 지문을 바꾸거나, 그 지문에 맞추기 위해 추천 내용·시간·원장을 소급 수정하지 않는다.
5. 원본 CSV와 토론 파일을 운영자에게 전달할 때도 **Claude가 진행하는 대화를 거치지 않는다.** 운영자는 실전 파일을 GitHub에 직접 올린다.
6. 08:30 이전 CSV 공개는 `early_reveal`로 기록되므로 하지 않는다. 원본·토론 내용이 담긴 다른 파일이나 커밋 내역도 지문 push에 함께 포함하지 않는다.

## 4. 준비·분석 기준

- 가격 제외판 snapshot의 실제 파일과 SHA-256을 확인한다. 라운드 날짜에 적용되는 최신 universe의 참조와 해시도 확인한다.
- 06:50 자료에는 가격이 없다는 전제로 진행한다. 가격을 추가 검색하면 URL·기준일·실제 확보 시각을 남긴다. 확인 못한 가격·배당·분할·이벤트는 추정으로 채우지 않는다.
- 공통 자료의 최근 14일 DART 목록을 먼저 보고 실적·IR 등 이벤트를 확인한다. 기사만 있고 공시에서 확인하지 못한 내용은 `공시 미확인`이라고 표시한다.
- 출처의 기준일을 모르면 `확인 못함`, 월까지만 알면 `2026-10`처럼 확인한 범위만 쓴다. 받은 날짜를 기준일 대신 넣지 않는다.
- 확보 시각은 자료 수령 후 실제 측정한 값이다. 여러 자료를 받은 직후 측정한 하나의 상한 시각을 함께 사용할 수 있으나, 받기 전 시각이나 추정 시각은 쓰지 않는다.
- 실제 승인된 활성 에이전트와 지침 버전으로만 분석한다. 정상 인원은 5명이며 각자 열린 시장마다 1종목을 고른다. 빈자리는 운영 규칙에 따른다.
- 같은 종목을 골라도 강제로 분산하지 않는다. 한국 종목코드는 영문을 포함할 수 있는 문자열로 보존하고, 미국 종목 표기도 universe의 문자열 그대로 쓴다.
- 기준가는 정규장 공식 종가다. 장외 정보는 마감 전 공개된 근거로만 참고하며 기준가로 대체하지 않는다.
- 상대 팀의 당일 CSV·토론·공용 추천 원장·관련 diff나 미리 생성된 파일을 마감 전에 보지 않는다. 마감 후의 상대 정보도 이미 동결한 추천에 반영하지 않는다.
- 08:30 이후 나온 정보로 CSV·선정 이유·위험·토론 기록을 보강하지 않는다. 공개 단계는 사전에 확정한 내용을 그대로 전달하는 단계다.

## 5. CSV 검증과 원본 동결

아래는 운영자가 공지한 명령 형식이다. 첫 실전 전 최신 `tools/league.py`에서 지원 여부와 동작을 확인한다. 현재 문서 작성만으로 새 명령을 실행·검증한 것은 아니다.

```bash
python3 tools/league.py schedule 2026-11-09 --to 2026-11-09
python3 tools/league.py import-csv league/imports/shushu/2026-11-09.csv --team shushu --dry-run
python3 tools/league.py commit league/imports/shushu/2026-11-09.csv
```

날짜는 실제 라운드로 바꾼다. `commit` 명령이 만든 `league/imports/shushu/<날짜>.sha256`을 사용하며, 지문 파일 문법을 임의로 만들지 않는다. `commit`은 지문 생성 절차이며, 이를 실행했다는 사실만으로 GitHub에 제출됐다고 보고하지 않는다.

동결 전 확인:

- CSV 헤더·UTF-8·활성 id·승인 버전·시장·대상 종목·중복·열린 시장 누락을 검증한다.
- `locked_at`은 실제 확정 시각이고 `+09:00`을 포함한다. 지문 push 시각보다 늦을 수 없다.
- 근거·위험·출처·기준일이 채워져 있으며 출처 확보 시각은 실제 관측값이다.
- CSV에는 가격을 넣지 않는다. 가격과 채점은 운영자 공통 원장을 사용한다.
- 제출 대상 파일만 검증한다. 이미 accepted된 추천을 시험 삼아 다시 제출하지 않는다.

동결 후 보존:

- CSV 원본을 파일로 보존한다. 스프레드시트·텍스트 편집기로 열어 다시 저장하거나 내용을 복사해 새 CSV로 만들지 않는다.
- CRLF/LF, BOM, 인코딩, 열 순서, 따옴표, 공백, 마지막 줄바꿈을 포함한 **모든 바이트**가 지문 생성 때와 같아야 한다.
- 전송은 원본 파일 그대로 한다. Git 줄바꿈 변환이나 업로드 과정에서 바이트가 달라지는지 확인한다. 자동 정규화를 막는 방법을 검증하지 못했다면 실전 전에 운영자와 해결한다.
- 저장소에서 올릴 파일 목록을 확인해 지문 단계에는 `.sha256` 하나만 포함한다. 무조건 전체 폴더를 추가하는 방식은 쓰지 않는다.
- 동결한 CSV, 생성된 지문, 최종 토론 기록을 안전하게 보관한다. 토론 파일도 사후 분석으로 바꾸지 않는다.

## 6. 접수 확인과 오류 처리

| 상황 | 처리 |
|---|---|
| 지문 push 완료, 영수증 대기 | 실제 push와 실행 상태를 확인한다. 로컬 완료만으로 `committed` 또는 `accepted`라고 보고하지 않는다. 불확실한 제출을 무작정 반복하지 않는다. |
| 08:30 전 지문 push가 확인됨 | 서버 시각·커밋 SHA·영수증·지문을 보존한다. `committed`여도 원본 공개가 남았음을 표시한다. |
| 지문이 08:30 이후 도착하거나 지문 없이 늦은 CSV만 제출 | `late`/미제출로 기록한다. 소급 제출·시각 변경·임의 예외 적용을 하지 않는다. |
| 첫 지문 접수 후 CSV 오류를 발견 | 지문을 바꾸지 않는다. 내용 수정본으로 교체하지 말고 운영자에게 보고한다. 지문과 같은 파일만 원본 공개 대상으로 유지한다. |
| 원본 해시 불일치로 rejected | 동결 사본·Git 저장 바이트·전송 경로를 확인한다. 12:00 전에 **첫 지문과 일치하는 원본**을 다시 올린다. 새 지문 또는 사후 수정 내용으로 통과시키지 않는다. |
| 12:00까지 원본 미공개 | 미제출로 기록하고 원인을 남긴다. 소급 인정 없음. |
| 실수로 마감 전 CSV 공개 | `early_reveal` 사실을 즉시 운영자에게 알린다. 원장이나 기록을 삭제·수정해 숨기지 않는다. |
| 서비스·사용 한도·자료·전송 장애 | 실제 시각과 단계·영향을 남겨 운영자에게 보고한다. 장애 사유는 운영 측 장애 기록·화면에 반영하며 마감은 임의 연장하지 않는다. |
| 자료·주간 결정·승인 버전이 확인되지 않음 | 없는 데이터나 명단을 지어내지 않는다. 준비되지 않은 부분과 제출 영향만 정확히 보고한다. |

서버 push 시각을 확보하지 못할 때의 대체 시각·판정은 최신 v1.7 엔진과 안내서에 따른다. 과거 규칙의 대체 기준을 새 제출 방식에 임의로 이식하지 않는다. 두 서버 시각 모두 확인되지 않은 제출을 자체적으로 정시 접수라고 판정하지 않는다.

## 7. 기록·주간 운영

- 추천 CSV, 토론, 출처, 실제 단계별 시작·종료, 지문·원본 해시, 커밋 SHA, 실행 ID, 두 단계 영수증을 보존한다.
- 기존 원장은 수정하지 않는다. 해시·채점 오류가 발견되면 원기록과 별도의 정정 기록을 남기는 운영 절차를 따른다.
- 토요일 복기는 잠정 점수를 구분하고, 확정되면 보완 기록을 추가한다. 원래 복기를 덮어쓰지 않는다.
- 지침 개선은 에이전트당 최대 3개, 반복된 판단 오류와 근거 pick_id 2건 이상을 기준으로 제안한다. 사용자 승인 전 새 버전을 적용하지 않는다.
- 월요일 06:30 주간 마감의 고정 기록에 따라 활성 인원과 대기 후보를 정한다. 새 합류자는 승인된 순서와 관점 제한을 지켜 같은 날 07:05 분석부터 참가한다.
- 점수는 모의 예측 점수이며 실제 매매 수익률·투자 권유가 아니다. 합산점은 포트폴리오 누적 수익률로 표현하지 않는다.

## 8. 실전 전 확인할 사항과 이 문서의 상태

- [ ] 최신 `docs/codex-team-guide.md` v1.7 및 `docs/codex-notices/2026-11-05-v1.7-commit-reveal.md` 수령·대조
- [ ] `commit`과 commit/reveal 영수증을 지원하고 원본 바이트 해시 버그가 수정된 검증기·워크플로 버전 확인
- [ ] 운영자의 지문 전송·원본 공개 담당과 시간 확보, 원본 파일 보존·전송 경로 확인
- [ ] 첫 라운드 공통 자료, 적용 universe, 활성 명단과 승인 버전 확인
- [ ] 지문과 Git에 저장되는 원본의 바이트 동일성을 확인하는 방법 확보

운영자는 실제 GitHub에서 `committed` → `accepted`를 시험했다고 보고했다. 슈슈 팀은 해당 최신 코드와 영수증을 아직 직접 검증하지 않았다. 이번 작업은 절차서 수정이며 실전 추천 생성·push·예약 자동화 활성화는 하지 않았다.

추가 연습은 필수가 아니다. 별도 요청 또는 필요 확인 후 실시할 경우에만 운영자가 안내한 `league/imports/sandbox-shushu/2026-11-10.sha256` → 같은 이름의 `.csv` 순서를 사용한다. 조기 시험의 `early_reveal` 허용은 이 연습에만 해당하며 실전에 적용하지 않는다.
