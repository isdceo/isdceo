# 개선안 — 마감 뒤 정보 차단 강화 (2026-11-18, 2차 초안)

운영자 요청("1번 개선안으로 정리해줘", 2026-11-18). 참고: TauricResearch/TradingAgents가 v0.3.1~v0.7.1에서 반복해 고친 '기준 시점 뒤 정보 섞임'(look-ahead, point-in-time) 문제를 우리 리그에 비춰 본 것이다. 코드는 가져오지 않았다(공개 README만 참고).

**상태: 제안. 아무것도 바뀌지 않았다.** 1차 초안(같은 날)에 대한 검토 의견을 반영해 고쳤다(아래 7장).

## 1. 지금 우리 리그는 어디까지 막고 있나

백테스트와 달리 우리는 **실시간 리그**다. 08:30 전에 고르면 그 뒤 정보는 아직 존재하지 않으므로, 큰 구멍은 구조적으로 막혀 있다.

| 장치 | 무엇을 막나 |
|---|---|
| 지문(08:30 전 push) → 원본(지문과 같은 바이트) | 마감 뒤 종목·근거 바꾸기 |
| 판정 = GitHub 서버 push 시각 | 커밋 시각·`locked_at` 조작 |
| 출처 `retrieved_at` > 08:30이면 행 거부 (`import_csv`) | 마감 뒤 받은 자료 인용 |
| 동시 공개(두 팀 원본 접수 또는 12:00 뒤) | 상대 팀 종목 보고 따라 하기 |
| v2.2 원본 접수 마감 08:55(스위치 켜면) | 장 시작 뒤 원본 안 내기 |

실제 원장 확인(2026-11-18, 실전 출처 656개):
- `retrieved_at`은 656개 모두 있다(현재 선택 항목이지만 두 팀 모두 채움).
- `as_of`가 '확인 못함'·빈칸인 출처는 53개(8%)다.
- `as_of`가 라운드 날짜보다 뒤인 출처는 1개다(`2026-11-16-shushu-s4-KR`, "2026-11-18 예정행사"). 예정된 사건 날짜를 적은 것이라 마감 뒤 정보가 아니다. 지금 `as_of` 한 칸에 여러 뜻이 섞여 쓰인다는 신호다.

## 2. 남은 빈틈

1. **스스로 적는 시각:** `retrieved_at`·`as_of`는 에이전트가 적는다. 검사기는 형식과 08:30 이전인지만 본다.
2. **늦은 제출 예외:** 11/18 슈슈 제출(09:10:27 push, 한국장 개장 뒤)을 운영자 예외로 받았다. 08:30~push 사이 정보가 섞였는지 확인하는 절차가 없다.
3. **시각의 뜻이 한 칸에 섞임:** 지금 `as_of` 한 칸에 여러 날짜가 함께 들어간다. 그래서 자동 판정이 오판하기 쉽다(3장).
4. **분석 중 검색:** 라운드가 늦어져 08:30 가까이 검색하면, 08:30 직후 기사와 경계가 흐려진다.
5. **복기의 사후 정보:** 주간 복기는 결과를 보고 지침을 고친다. 의도된 학습이지만, 그 주 결과에만 맞춘 규칙이 되지 않게 하는 장치는 v2.1의 '같은 유형 2건 이상' 하나뿐이다.

## 3. 시각 용어 (먼저 나눈다)

한 출처에는 서로 다른 시각이 여럿 있다. 마감(08:30) 기준은 **"그 정보가 08:30에 이미 공개돼 있었는가"**에만 적용한다.

| 용어 | 뜻 | 08:30 기준 적용 |
|---|---|---|
| 최초 공개 시각 | 기사·공시·자료가 처음 공개된 시각 | **적용**: 08:30 전이어야 함 |
| 인용 버전 수정 시각 | 인용한 내용이 들어간 버전의 수정 시각(정정·업데이트) | **적용**: 인용한 내용이 08:30 전에 공개돼 있었어야 함 |
| 자료 기준일 | 데이터가 가리키는 기준(예: 3분기 실적, 11/17 종가) | 적용 안 함(과거 기준이면 정상) |
| 확보 시각 (`retrieved_at`) | 에이전트가 실제로 자료를 받은 시각 | 지금처럼 08:30 이전 검사 |
| 예정 행사일 | 앞으로 있을 실적 발표·배당락 등 날짜 | 적용 안 함(근거 본문에 쓰고 시각 칸에는 넣지 않음) |

지금 CSV의 `as_of` 한 칸은 이 중 '자료 기준일'로만 쓰는 것이 맞다. 공개·수정 시각을 따로 적을 칸은 두 팀 규칙 변경(6장 B1)이 필요해 보류한다.

## 4. 감사 판정 (세 가지)

출처 하나를 볼 때 판정은 셋 중 하나다. **'확인 불가'는 위반으로 치지 않는다.**

| 판정 | 조건 |
|---|---|
| 마감 전 공개 확인 | 원문을 열어 ① 최초 공개 시각이 08:30 전이고 ② 인용 버전도 08:30 전 것임(바뀌지 않는 자료이거나 수정 시각이 08:30 전)을 확인 |
| 마감 후 공개 확인 | 인용한 내용이 들어간 최초 공개·수정 시각이 08:30 뒤임이 원문으로 확인됨 |
| 확인 불가 | 라운드 당일 날짜만 있고 시각이 없음. 나중에 수정된 페이지라 인용 당시 버전을 알 수 없음. 열 수 없음. URL·공시번호 날짜만 있음. 최초 공개는 마감 전이지만 수정 이력을 모름 |

## 5. 이번 주 조치 (운영자 확인 대상, 점수·판정 불변)

## 7. 1차 초안에서 바뀐 점 (검토 의견 반영)

1. **시각 분리:** '게시·기준 날짜' 한 칸 안을 버리고, 시각 다섯 가지를 나눴다(3장). 08:30 기준은 공개 여부에만 적용한다.
2. **감사 판정 3분류:** 감사 판정을 셋으로 나누고, '확인 불가'는 위반이 아니라고 정했다(4장).
3. **A1 수정:** '경고'에서 '중립 통계'로 바꿨다. 08:00~08:30 몰림 표시를 뺐고, 예외는 '운영자 예외 승인'으로 표시한다.
4. **B4 재분류:** 실제 규칙 변경으로 분류하고, 장 시작 전 push만으로는 보장이 안 된다는 점을 적었다.
5. **A3 기록 방식:** 감사 결과는 별도 기록으로만 남긴다. 확인 불가는 위반이 아니고, 두 팀에 같은 기준을 적용한다.
6. **A4 수정:** 용어를 분리하고, 같은 해석을 두 팀에 공유하기로 했다.
7. **B안 보류:** B안은 모두 보류했다. B3는 경고·수동 검토로 먼저 시험한다.

## 8. 하지 않는 것

- 출처 URL을 자동으로 열어 공개 시각을 긁는 기능: 사이트마다 형식이 다르고 수정 이력이 남지 않는 곳이 많아 오판이 많다. 접속 제한·저작권 문제도 있다. 표본 감사로 대신한다.
- 에이전트 검색 차단(08:30 뒤 인터넷 끊기): 두 팀의 실행 환경 제어 방식이 다르고, 마감 전 분석에는 필요 없다.
