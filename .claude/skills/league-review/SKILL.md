# Claude 팀 주간 복기

너는 **복기 진행자**다. 에이전트가 자기 추천을 돌아보게 하고, 개선안을 **제안**으로만 올린다. 승인과 적용은 운영자가 PR을 머지할 때 이루어진다.

인자: `$ARGUMENTS` (주차가 없으면 KST 기준 이번 주)

## 원칙

- **과거 점수와 추천은 절대 바꾸지 않는다.** 복기는 새 파일로 추가만 한다.
- "학습했다", "스스로 개선했다"는 표현을 쓰지 않는다. **"분석 지침 v2 제안"**, 승인 후에는 **"분석 지침 v2 적용"**이라고 쓴다.
- **한 주 표본은 작다** (에이전트당 최대 10건). 결과 하나에 맞춘 변경, 특정 종목·업종을 고정으로 넣거나 빼는 변경은 금지한다. 같은 유형의 판단 오류가 **2건 이상** 반복됐거나 규칙 위반·자료 누락처럼 결과와 무관한 문제만 개선 대상이다.
- 개선안은 에이전트당 **최대 3개**로 한다. 각 개선안에는 근거가 된 `pick_id`를 붙인다.
- 리그 규칙(마감, 채점, 대상 범위, 출처 표기)은 지침에서 바꿀 수 없다. 규칙 변경은 운영자 결정 사항이다.
- 슈슈 팀(Codex)의 복기는 Codex가 따로 한다. 이 스킬은 Claude 팀만 다룬다. 상대 팀 파일은 읽어도 되지만(마감 지난 과거 자료), 상대의 지침을 베끼는 개선안은 만들지 않는다.

## 1단계 — 자료 준비

1. `git pull`로 최신 원장을 받는다.
2. `python3 tools/league.py review-data <주차>` → `league/reviews/<주차>/claude/data.json`으로 저장한다.
3. 확정되지 않은 추천(`status`가 `final`이 아닌 것, 보통 금요일 미국분)이 있으면 목록을 따로 적어 둔다. 복기 문서에 **잠정**으로 표시해야 한다.
4. `python3 tools/league.py guideline-check --dry-run`으로 현재 지침이 승인된 버전과 같은지 확인한다. `unapproved_edit`가 있으면 멈추고 운영자에게 보고한다.

## 2단계 — 에이전트별 복기 (병렬)

이번 주 순위표에 있는 에이전트마다 Agent 도구로 실행한다(`subagent_type` = 에이전트 id).
- 이번 주 **탈락자**도 복기는 쓴다. 하지만 개선안은 만들지 않는다(다음 주부터 뛰지 않으므로).
- 프롬프트:

> AI 투자 리그 <주차> 주간 복기. 너의 현재 분석 지침은 v<버전>이다.
> `league/reviews/<주차>/claude/data.json`에서 너(<id>)의 추천과 결과를 읽어라. 확정/잠정 상태를 구분하라.
> `league/rounds/<날짜>/claude/r1-<id>.md`, `r2-<id>.md`에서 당시 분석 원문도 확인하라.
> 아래 형식으로 `league/reviews/<주차>/claude/<id>.md`를 작성하라.
> 1. 결과 요약: 건수, 평균, 초과 점수, 잠정 건수
> 2. 추천별 복기: 당시 핵심 가정 → 실제 결과 → 가정이 맞았는지/틀렸는지/판단 불가
>    - 하루 수익률은 잡음이 크다. 결과만으로 판단하지 말고 가정 자체를 검토하라.
> 3. 틀린 가정, 놓친 위험, 자료 누락 (반복된 것과 1회성을 구분)
> 4. 개선안 (최대 3개): 각 항목에 근거 pick_id, 바꿀 지침 문장(전/후), 기대 효과, 부작용
>    - 반복 근거가 없으면 "개선안 없음"이라고 써라.
> 5. 결론: 지침 변경 제안 여부
> 개선안이 있으면 현재 지침(`.claude/agents/<id>.md`)을 바탕으로 수정한 **전체 파일**을 `league/agents/claude/<id>/v<버전+1>.md`에 써라.
> 앞부분(frontmatter)의 name·tools는 바꾸지 말고, 리그 규칙에 해당하는 부분은 고치지 마라.
> 마지막에 JSON을 반환하라: `{"agent_id":"<id>","proposal":true|false,"changes":[{"pick_ids":["..."],"summary":"..."}]}`

## 3단계 — 점검과 PR

1. 각 개선안을 원칙에 맞는지 점검한다.
   - 근거 pick_id가 2건 이상인가 (또는 규칙·자료 문제인가)
   - 종목·업종을 고정하지 않는가
   - 리그 규칙을 건드리지 않는가
   - 원칙에 어긋나면 해당 에이전트에게 SendMessage로 수정을 요청하거나 그 개선안을 뺀다.
2. **개선안이 하나도 없으면:** 복기 문서와 data.json만 현재 브랜치에 커밋·push하고 끝낸다.
3. **개선안이 있으면:**
   - 새 브랜치 `league-review/<주차>`를 만든다.
   - 복기 문서와 data.json을 커밋한다.
   - 개선안이 있는 에이전트마다: `league/agents/claude/<id>/v<N+1>.md`(보관본)를 추가하고, 같은 내용으로 `.claude/agents/<id>.md`를 교체한다. 그리고 `league/agents/roster.json`에서 그 에이전트의 `version`을 N+1로 올린다.
   - push한 뒤 현재 기본 브랜치를 대상으로 **PR을 만든다. 머지는 하지 않는다.**
4. PR 본문:
   - 주차, 순위 요약, 잠정 건수
   - 에이전트별 개선안 표: 에이전트, v N→N+1, 변경 요약, 근거 pick_id
   - 승인 안내:
     - "머지 = 승인입니다. 머지 후 첫 라운드부터 새 지침이 적용되고 `guideline-check`가 적용 시작일을 기록합니다."
     - "일부만 승인하려면 해당 에이전트 파일만 남기고 나머지는 되돌려 주세요."
   - 주의 문구: "한 주 결과로 실력을 판단할 수 없습니다. 반복된 판단 오류만 다뤘습니다."

## 4단계 — 확정 후 보완 (다음 주 초)

토요일 복기에서 잠정이었던 추천이 확정되면, `league/reviews/<주차>/claude/<id>-addendum.md`에 확정 결과와 복기 보완을 **추가**한다. 원래 복기 문서는 고치지 않는다.

## 보고 (사용자에게)

- 주차, 에이전트별 복기 요약 한 줄씩
- 개선안 수와 PR 링크 (없으면 "지침 변경 제안 없음")
- 잠정 상태로 남은 추천 수와, 보완이 필요한 날짜
