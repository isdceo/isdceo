# 리그 게임 화면 작업

대상: `league/play/src.html` (빌드: `league/play/build.py`, 배포: `tools/league.py build-site`).
목표는 "대시보드"가 아니라 **테이블에 앉은 캐릭터가 카드를 쪼여 보여 주는 게임 장면**이다. 보고는 한국어로 한다.

참고: OpenAI Game Studio 플러그인의 game-ui-frontend·game-playtest 스킬(https://github.com/openai/plugins, plugin.json에 MIT 표기)의 원칙을 읽고 우리 리그에 맞게 새로 썼다. 원문을 옮기지 않았다.

## 절대 지킬 것 (어기면 작업을 멈추고 보고)

- **가격 숫자 금지.** 원·달러·₩·$, 종가, 목표주가를 화면에 쓰지 않는다. 점수(%)·순위·종목명만.
- **돈·베팅 요소 금지.** 재화(코인·보석), 뽑기·상자, 출석 보상, 잭팟·대박 상금 같은 표현, 베팅·예측 내기. 바닥 글 "모의 예측 게임 · 돈·베팅 없음"을 지운다면 이유를 보고한다.
- **마감 전 종목 금지.** 결과 묶음(`dashboard_data.bundle()`)이 주는 것만 쓴다. 화면에서 원본 파일을 따로 읽지 않는다.
- **출처 표시 유지.** "한국거래소 통계정보", 미국 데이터 출처(현재 Alpha Vantage).
- **실존 인물 흉내 금지.** 캐릭터는 애칭·스타일명으로만. 특정 게임의 그림·이름·효과음·카드 틀을 그대로 옮기지 않는다(원리만).
- 외부 글꼴·스크립트를 새로 불러오지 않는다. 글꼴은 `league/play/fonts/`(OFL)만.

## 화면 원칙

1. **장면이 먼저, 글은 나중.**
   - 첫 화면은 몇 초 안에 "캐릭터를 눌러 보고 싶은" 장면이어야 한다.
   - 늘 떠 있는 정보는 한 군데(상단 띠 하나)와 작은 보조 하나까지만 둔다.
   - 테이블 가운데와 아래 가운데는 비워 둔다.
2. **긴 글은 서랍 안에.**
   - 규칙, 기록, 종목 목록, 설정은 메뉴 창(sheet)에 둔다.
   - 첫 화면에 표나 문단을 펼치지 않는다.
3. **글은 움직임 위에서도 읽혀야 한다.** 말풍선·이름판에 받침 판, 테두리, 대비를 준다. 흐림 효과는 휴대폰에서 줄인다(`pointer:coarse`).
4. **정보 순서.** 확대 화면에서는 캐릭터 → 대사(한 줄 이유) → 카드 → 점수 순이다. 점수는 카드를 다 젖힌 **뒤에** 나온다.
5. **움직임은 의미 있을 때만.**
   - 강한 연출은 공개 순간, 큰 움직임(±3%·±5%), 탈락, 첫 방문 안내에만 쓴다.
   - 모든 요소가 늘 흔들리지 않게 한다.
   - `prefers-reduced-motion`과 "연출 빠르게"(localStorage `league.fast`)를 존중한다.
   - 빈 곳을 누르면 연출을 건너뛸 수 있어야 한다.
6. **손맛.**
   - 공개 정도는 손가락을 따라간다.
   - 누르면 살짝 눌렸다 튀어 오른다.
   - 진동(`buzz`)은 안드로이드에서만 나온다. 소리(`sfx`)는 기본 꺼짐이다.
7. **휴대폰 먼저.**
   - 세로(390×844), 가로(844×390), 작은 폰(375×667)을 처음부터 같이 본다.
   - `100dvh`와 안전 영역(`env(safe-area-inset-*)`)을 쓴다.
   - 가로 스크롤이 없어야 한다.
   - 누르는 영역은 최소 24px, 권장 44px이다.
8. **게임 화면이지 관리 화면이 아니다.**
   - 쓰지 말 것: 회색 카드 상자를 사방에 고르게 늘어놓은 배치, 기본 글꼴, 테마 없는 평평한 버튼.
   - 메뉴 창도 테이블·카드 세계의 재질(펠트, 나무, 금속 테두리)을 따른다.

## 작업 순서

1. **방향 먼저 정하기.** 바꿀 부분의 목적, 누가 무엇을 누르는지, 휴대폰에서 어디에 놓일지, 피할 것을 3~5줄로 적고 시작한다. 큰 변경이면 사용자에게 먼저 보여 준다.
2. **고치기.** `league/play/src.html`만 고친다. 색·크기는 CSS 변수로 둔다.
3. **만들기와 테스트.**
   ```
   python3 league/play/build.py <스크래치 폴더>
   node league/play/playtest.js <스크래치 폴더>          # 확인용 1배, 사용자에게 보여 줄 때는 --scale 2
   python3 -m unittest discover -s tests -q
   ```
   - `playtest.js`는 기기 6종(세로·가로·작은 폰·큰 폰·데스크톱·동작 줄이기)에서 다음 흐름을 해 보고 스크린샷을 `<폴더>/playtest/`에 남긴다.
     - 첫 화면 → 캐릭터 열기 → 카드 끝까지 밀어 공개 → Esc 닫기 → 메뉴 창 → 결과 쇼
   - 동시에 JS 오류, 가로 스크롤, 화면 밖 버튼, 24px 미만 터치 영역을 잡는다. 실패가 있으면 종료 코드 1이다.
4. **스크린샷 직접 보기.** 기계 점검을 통과해도 아래는 그림으로만 판단된다. 최소 폰세로·폰가로의 첫 화면과 공개 화면은 열어 본다.
   - 글자 겹침, 잘림, 말풍선이 카드나 캐릭터를 가리는지
   - 상단 띠·버튼이 장면을 얼마나 덮는지(휴대폰 세로에서 늘 떠 있는 UI가 화면의 25%를 넘지 않게)
   - 점수 색(상승 초록·하락 빨강·보합 금색·채점 전 회색)이 바로 읽히는지
5. **독립 검수.** 큰 변경 뒤에는 별도 에이전트에게 검수를 맡긴다.
   - 넘길 것: 스크린샷 경로와 이 문서의 "화면 원칙"·"절대 지킬 것"만. 내 판단은 넘기지 않는다.
   - 받을 것: 심각한 순서의 문제 목록. 각 항목에 보이는 현상, 재현 방법, 왜 문제인지, 고칠 곳(src.html의 CSS·JS·데이터 중 어디)이 있어야 한다.
   - 고치고 다시 검수한다. "문제 없음"이 나올 때까지 반복하되, 같은 지적이 세 번 돌아오면 사용자에게 판단을 묻는다.
6. **미리보기 공유.** 사용자에게 보여 줄 때는 기존 게임 미리보기 Artifact(비공개)를 같은 주소로 갱신한다. 새 주소를 만들지 않는다.
7. **커밋.** src.html, playtest.js 등 바뀐 파일만 커밋한다. 스크린샷과 빌드 결과는 커밋하지 않는다.

## 점검표 (보고 전에 확인)

- [ ] 첫 화면이 장면으로 읽힌다(스크린샷을 축소해 봐도 "게임"으로 보인다)
- [ ] 캐릭터·이름판을 누르면 바로 열린다. 첫 방문 안내가 떠 있어도 눌린다
- [ ] 카드가 손가락을 따라 젖혀지고, 다 젖힌 뒤에만 점수가 나온다
- [ ] 채점 전·잠정 점수는 굴리거나 축하 연출을 하지 않는다
- [ ] Esc·닫기 버튼·빈 곳 누르기로 확대 화면과 메뉴 창이 닫히고, 포커스가 원래 자리로 돌아간다
- [ ] 화면을 돌려도(세로↔가로) 안내·창이 이상한 위치에 남지 않는다
- [ ] 동작 줄이기에서 흔들림·빛 번짐이 꺼지고 기능은 그대로다
- [ ] 아이폰은 진동이 없어도 그림 효과로 충분히 전달된다
- [ ] 가격 숫자·돈·베팅 표현이 화면 어디에도 없다
- [ ] 출처 표시가 보인다

## 보고 형식

- 바꾼 것 3줄 이내
- 플레이테스트 결과(기기별 통과·실패)와 대표 스크린샷 1~2장(사용자에게 보낼 때는 `--scale 2`)
- 독립 검수 결과: 남은 문제와 그대로 둔 이유
- 커밋 SHA
