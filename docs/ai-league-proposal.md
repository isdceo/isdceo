# AI 투자 리그 설계 제안서

> 상태: **규칙 v1 확정 (배당만 미정)** · 1단계(원장·채점 엔진) 구현 완료 · 작성일 2026-11-03
> 실제 주문·계좌 연결 없음. 모든 점수는 이미 확정된 종가로 계산하는 **모의 예측 평가**이며 투자 권유가 아니다.

---

## 0. 핵심 결정 요약

| 항목 | 제안 |
|---|---|
| 라운드 시각 | **매 평일 KST 07:00 수집 → 08:30 확정 (한 번에 한국·미국 동시 처리)** |
| 기준가격 | 각 시장의 *직전 정규장 종가* (추천일 종가) |
| 평가가격 | 각 시장의 *다음 정규장 종가* |
| 점수 | `((평가 종가 × 분할보정 + 평가일 현금배당) ÷ 기준 종가 − 1) × 100`, 소수 둘째 자리 (보정이 없으면 요청서 공식과 같음) |
| 저장 방식 | 저장소 안의 **추가 전용(append-only) JSONL + 해시 체인 + git 이력** |
| 추천 단위 | **에이전트마다 한국 1 + 미국 1** (그날 열린 시장 모두 필수, 팀당 하루 최대 10건) |
| 참고 지표 | 주가 변동 점수, **시장 대비 초과 점수**(KOSPI·S&P 500 대비) — 순위 미사용 |
| 교체 조건 | 주간 평균 최하위 1명. 단, **최하위 확정 6건 미만·완전 동점·팀 확정 30건 미만 주간은 교체 보류** |
| 개선안 적용 | 에이전트 지침 변경을 **PR로 올리고 사용자가 머지 = 승인** |
| 자동화 | 토론: Claude Code 예약 작업(구독 한도 내) · 채점: GitHub Actions(LLM 불필요) |
| 데이터 | 1단계는 예시 데이터만. 실제 시세는 이용조건 확인 후 연결 |

### 왜 KST 08:30 한 번으로 충분한가

```
        KST  D일 15:30        D+1일 06:00(서머타임 05:00)      D+1일 08:30       D+1일 09:00
한국    ──── 정규장 마감 ────────────────────────────────────────────────────── 개장 ──
미국                        ──── 정규장 마감 ────
리그                                                    수집 07:00 → 확정 08:30
```

08:30 KST에는 한국 D일 종가와 미국 D일(현지) 종가가 모두 확정돼 있고 두 시장 모두 아직 다음 장이 열리기 전이다. 그래서 **같은 시점의 같은 자료**로 5명이 토론하고, 어느 시장 종목을 고르든 "장 마감 후 확정" 조건을 동시에 만족한다.

## 2. 데이터 구조

DB 서버 없이 **저장소 파일 + git**으로 운영한다. 무료이고, git 이력 자체가 감사 기록이 된다.

```
league/
  rules.md                      # 규칙 (버전 관리)
  universe.json                 # 대상 종목 범위
  agents/
    roster.json                 # 에이전트 명단·상태
    buffett/v1.md, v2.md         # 에이전트별 분석 지침 (버전별 파일, 수정하지 않고 새 버전 추가)
  rounds/2026-11-04/
    snapshot.json               # 토론에 쓴 공통 자료 (+ sha256)
    debate.md                   # 토론 원문
  ledger/
    picks.jsonl                 # 추천 (추가 전용)
    prices.jsonl                # 기준·평가 종가 기록 (추가 전용)
    scores.jsonl                # 채점 결과 (추가 전용)
    corrections.jsonl           # 정정 기록 (원본 수정 대신 추가)
    imports/claude-team/*.csv   # 외부 팀 제출 원본
  weekly/2026-W45.json          # 주간 순위·교체 결정
  reviews/2026-W45/buffett.md   # 주간 복기
```

### picks.jsonl (한 줄 = 추천 1건)

```json
{
  "pick_id": "2026-11-04-claude-buffett",
  "team": "claude",
  "agent_id": "buffett", "agent_version": 2, "agent_label": "가치형 (버핏의 공개된 원칙 참고)",
  "round_date": "2026-11-04",
  "market": "KR", "ticker": "005930", "name": "삼성전자",
  "base_session": "2026-11-03",
  "locked_at": "2026-11-04T08:27:13+09:00",
  "snapshot_sha256": "9f2c…",
  "rationale": "…", "risks": ["…"],
  "sources": [{"title": "…", "url": "…", "as_of": "2026-11-03"}],
  "prev_hash": "a81e…", "hash": "c4d0…"
}
```

- **가격은 추천 레코드에 넣지 않는다.** 추천은 08:30에 잠그고, 기준 종가는 공식 확정치가 나오면 `prices.jsonl`에 따로 기록한다. 추천 시점에 가격이 아직 공식 확정되지 않아도 추천은 확정할 수 있고, 가격 오류가 생겨도 추천 자체를 건드리지 않는다.
- `hash = sha256(이 줄 내용 + prev_hash)` 해시 체인. 과거 줄을 고치면 이후 모든 해시가 깨진다.
- CI 검사: `ledger/*.jsonl` 변경이 **파일 끝에 줄 추가**가 아니면 실패시킨다.

## 3. 규칙 제안

### 3-1. 라운드와 확정

- 대상 범위(제안): 🇰🇷 KOSPI200 + KOSDAQ150 / 🇺🇸 S&P 500 + NASDAQ-100. 양 팀 동일.
- 07:00 KST에 공통 자료(`snapshot.json`)를 만들고 해시를 기록한다. 이후 토론은 이 자료만 공통 근거로 쓰고, 개별 에이전트가 추가로 찾은 자료는 출처·기준일을 붙인다.
- 08:30 KST 마감. 마감까지 확정하지 못한 에이전트는 그날 **미제출**(점수 없음, 평균에서 제외, 미제출 횟수는 표시).
- 휴장: 한국 기준 휴장일이면 그날 한국 종목은 고를 수 없고, 미국 기준도 같다. 두 시장 모두 휴장이면 라운드가 없다.
- 거래일 판정은 거래소 달력 라이브러리(예: `exchange_calendars`의 XKRX, XNYS)로 하고, 임시 휴장(선거일 등)은 `league/calendar_overrides.json`에 수동으로 추가한다.

### 3-2. 채점

- `점수 = ((평가 종가 × 분할보정 + 평가일 현금배당) ÷ 기준 종가 − 1) × 100`
  - **분할·병합**: 평가일이 권리락·분할 기준일이면 비율로 보정한다. 예: 1→10 분할이면 평가 종가 × 10.
  - **배당**: 평가일이 배당락일이면 주당 현금배당을 더한다. 배당락 하락을 손실로 보지 않기 위해서다. 원하면 "배당 제외"로 바꿀 수 있다(결정 필요).
  - 수수료·세금·환율은 포함하지 않는다.
- **잠정 → 확정**: 평가일 다음 영업일에 다시 조회해 값이 같으면 `final`로 바꾼다. 다르면 정정 기록을 남기고 새 값으로 확정한다. 순위에는 `final`만 쓴다.
- 확정 후 오류가 발견되면 `corrections.jsonl`에 정정 줄을 추가하고, 화면에 `⚠ 정정됨`과 정정 전후 값을 표시한다. 원래 줄은 지우지 않는다.

### 3-3. 보류·무효

| 상황 | 처리 |
|---|---|
| 가격 미확인 (제공처 누락 등) | `held`. 0점 처리하지 않음. 3영업일 안에 확인되면 채점 |
| 평가일 거래정지 | `held`. 재개 후 첫 종가로 채점하고 "지연 채점"으로 표시. **5영업일 넘게 정지되면 `void`**(평균에서 제외) |
| 상장폐지·정리매매 | `void` + 사유 기록. 사용자 확인 후 확정 |
| 대상 범위 밖 종목 | 확정 단계에서 거부 (재선정 기회 1회) |

### 3-4. 주간 순위와 교체

- 주간 = 월~금 라운드. 다음 주 월요일 07:00에 집계하며, 그 시점까지 `final`인 점수만 반영한다.
- 순위 = 주간 평균 점수. 동점(소수 둘째 자리 기준)이면 ① 중앙값 → ② 최저점이 높은 쪽 → ③ 그래도 같으면 둘 다 생존.
- **교체 보류 조건** (하나라도 해당되면 그 주는 탈락 없음):
  - 최하위 에이전트의 채점 완료가 **6건 미만** (정상 10건)
  - 전체 50건 중 채점 완료가 30건 미만 (데이터 장애 주간)
  - 최하위 동점이 규칙 ③까지 가는 경우
- 탈락 에이전트는 `status: eliminated`로 바꾸기만 하고 기록은 그대로 보존한다.
- 대체 에이전트는 **대기 후보 풀**에서 다른 투자 관점 순서대로 투입한다. 예: 모멘텀형, 퀀트 팩터형, 배당형, 소형 성장형, 이벤트 드리븐형, 한국 밸류업형. 탈락한 관점은 4주 동안 재투입하지 않는다.

> ⚠ **통계 주의:** 한 주 5건은 운이 대부분이다. 매주 탈락 방식은 재미 요소로는 좋지만, 실력 평가로는 의미가 약하다. 대안으로 *"최근 4주 누적 평균 최하위"* 또는 *"2주 연속 최하위"*를 제안하며 선택 사항으로 둔다.

### 3-5. 에이전트 개선 (승인제)

1. 주간 집계 직후 각 에이전트가 자기 추천을 복기한다: 틀린 가정, 놓친 위험, 지침 개선안 (`reviews/` 문서).
2. 개선안은 `agents/<id>/v{n+1}.md` 새 파일로 **PR**을 연다. PR 설명에 변경 이유와 근거가 된 추천 ID를 적는다.
3. 사용자가 **머지하면 승인**, 닫으면 반려. 승인된 버전은 *다음 라운드부터* 적용되고, 추천 레코드에 `agent_version`이 남는다.
4. 화면과 문서에서는 "학습했다"는 표현 대신 **"분석 지침 v2 적용"**으로 쓴다. 과거 점수는 바꾸지 않는다.

### 3-6. 명칭

실제 인물이 추천한 것처럼 보이지 않도록 에이전트 이름은 **스타일명**으로 쓴다(예: "가치형", 부제 "버핏의 공개된 원칙 참고"). 기존 `buffett` 등 서브에이전트 파일은 내부 지침으로 재사용하되 화면 표시는 스타일명으로 한다. 13F 보유 현황은 실제 공시 데이터라 지금처럼 실명으로 둔다.

## 4. 자동화 방법

| 작업 | 실행 수단 | LLM | 시각 (KST) |
|---|---|---|---|
| 공통 자료 수집 → snapshot 커밋 | GitHub Actions (cron) | ✗ | 평일 07:00 |
| 토론 → 추천 확정 → 커밋·푸시 | **Claude Code 예약 작업** (매번 새 세션, `/league-round` 스킬) | ✓ | 평일 07:10 → 08:30 전 완료 |
| 종가 수집 · 채점 · 잠정→확정 | GitHub Actions | ✗ | 평일 07:00 (전날 평가분), 18:00 (한국 당일분) |
| 주간 집계 · 교체 판정 | GitHub Actions | ✗ | 월 06:30 |
| 주간 복기 · 개선안 PR | Claude Code 예약 작업 | ✓ | 토 10:00 |
| 원장 위변조 검사 | GitHub Actions (PR·push 시) | ✗ | 수시 |
| 화면 배포 | GitHub Pages (정적 파일, 원장 JSON 읽기) | ✗ | 푸시 시 |

- 채점·집계는 모두 결정적인 파이썬 코드로 하고, LLM은 쓰지 않는다. 같은 입력이면 항상 같은 점수가 나와야 한다.
- 08:30 마감은 **커밋 시각이 아니라 레코드의 `locked_at`과 원격 푸시 시각**으로 검증한다. 08:30 이후 푸시된 추천은 CI가 거부한다.

### 비용 (무료 운영 목표, 유료 자동 전환 없음)

- **GitHub Actions**: 공개 저장소는 무료다. 비공개 저장소는 무료 분량 안에서 충분할 것으로 보이며, 현재 한도는 GitHub 요금 페이지에서 확인이 필요하다. 지출 한도(spending limit)를 0으로 두면 초과 시 중단될 뿐 과금되지 않는다.
- **GitHub Pages**: 공개 저장소에서 무료다. 비공개 저장소의 Pages나 접근 제한이 필요하면 별도 검토가 필요하다(4-1 참고).
- **Claude 토론**: 사용자의 Claude 구독 사용 한도 안에서 실행한다. 5명 × 3라운드를 매일 돌리면 사용량이 크므로 **매일은 "1라운드 분석 + 1회 반론 → 확정"으로 축소**하고, 3라운드 토론은 주 1회 복기에서만 하는 방식을 제안한다. 구독의 추가 사용(초과 과금) 옵션은 꺼둘 것. 별도 API 키 과금 방식은 쓰지 않는다.

### 6-1. 지인 전용 무료 호스팅

- 저장소는 **비공개**로 유지한다. GitHub Pages는 비공개 저장소에서 유료 요금제가 필요할 수 있어(확인 필요) 쓰지 않는다.
- 화면은 **Cloudflare Pages(무료)** 에 배포하고, **Cloudflare Access(Zero Trust 무료 플랜)** 로 지인 이메일만 허용한다. 지인은 이메일로 받은 일회용 코드로 로그인한다. 소규모 인원은 무료 범위로 알려져 있으나, 연결 전에 현재 무료 한도를 확인한다.
- 지인 화면에는 **종목명·점수·근거**만 보여주고 원시 시세 시계열은 표시하지 않는다. 데이터 재배포 부담을 줄이기 위해서다(약관 확인은 별도로 필요).
- 채점·집계용 GitHub Actions는 비공개 저장소의 무료 분량 안에서 돌린다. 하루 몇 분 수준이다. 지출 한도는 0으로 둔다.

### 6-2. 토론 강도 — Codex와의 공정 비교를 우선

두 팀을 비교하려면 **양 팀이 같은 절차**를 따라야 한다. 그래서 매일 진행 방식을 고정하고, 같은 절차서를 슈슈(Codex) 팀에도 전달한다.

| 단계 | 시각 (KST) | 내용 |
|---|---|---|
| 공통 자료 공개 | 07:00 | `rounds/<날짜>/snapshot.json` (+ sha256). **두 팀에 같은 파일 제공** |
| ① 독립 분석 | 07:05–07:40 | 5명이 서로 보지 않고 각자 분석 + 한국·미국 후보 각 1종목 |
| ② 반론 1회 | 07:40–08:10 | 다른 4명의 후보를 보고 반박·수정 |
| ③ 확정 | 08:10–08:30 | 한국·미국 최종 각 1종목 + 근거·위험·출처·기준일 → 원장 기록 |

- 매일 3라운드 대신 **분석 → 반론 1회 → 확정**으로 한다. 90분 안에 끝나야 하고 구독 사용 한도를 아껴야 해서다. 그래도 요청서의 "토론·반론 후 선정" 조건은 충족한다.
- 주 1회(토요일) 복기 때만 3라운드 전체 토론을 한다.
- 양 팀의 추가 자료 검색(웹 검색)은 허용하되, 출처·기준일을 반드시 기록하고 **08:30 이후 정보는 금지**한다.
