# 손실 복기 (마이너스 점수 자동 분석)

로로 팀 종목이 **확정(final) 마이너스 점수**를 받으면, 그 종목을 고른 에이전트에게 원인을 분석하게 하고 기록을 남긴다. 보고와 기록은 모두 한국어로 쓴다.

- 언제: 평일·토요일 10:30 채점 뒤 예약 세션(11:23 KST)이 돈다. 사용자가 요청하면 언제든.
- 인자: 없으면 실전(`league`). `연습`이면 `--dir league/sandbox`.

## 지켜야 할 것

- **지침을 바꾸지 않는다.** 복기는 기록일 뿐이다. "다음에 바꿀 점"은 주간 복기(`league-review`)가 모아 운영자 승인 절차(PR)로 올린다. `.claude/agents/*.md`, `league/agents/` 아래 파일, 명단을 고치지 않는다.
- **원 가격을 쓰지 않는다.** 원·달러 금액, ₩·$ 숫자, 목표주가를 쓰지 않는다. 수익률(%)과 지수 대비(%p)만 쓴다. 이 기록은 저장소에 남는다.
- **슈슈 팀 자료를 보지 않는다.** `league/imports/shushu/`, `league/inbox/shushu/`, `docs/codex-notices/replies/`, 슈슈 전용 저장소는 열지 않는다. 복기는 우리 팀 종목만 다룬다.
- **진행 중인 라운드와 섞지 않는다.** 이 세션은 그날 라운드 종목을 고르거나 고치지 않는다. 라운드 폴더(`league/rounds/<오늘>/claude/`)의 마감 전 파일을 열지 않는다.
- **숫자를 지어내지 않는다.** 사후에 찾은 자료는 URL과 확인 시각을 남긴다. 못 찾으면 "출처 확인 못함"과 이유를 쓴다. 실존 인물의 발언처럼 쓰지 않는다.
- 같은 종목은 한 번만 복기한다(검사를 통과한 파일이 있으면 건너뛴다. 실패한 파일은 다시 대상).

## 1단계 — 대상 찾기

```
git pull --rebase --autostash origin claude/web-vs-desktop-differences-ir8pm0
python3 tools/loss_review.py due --json          # 연습은 --dir league/sandbox
```

비어 있으면 "복기할 마이너스 확정 종목 없음"으로 보고하고 끝낸다. 한 번에 최대 10건까지만 처리하고, 남으면 보고에 적는다(다음 실행이 이어 받는다).

## 2단계 — 에이전트가 직접 분석 (병렬)

대상마다 Agent 도구로 **그 종목을 고른 에이전트**(`subagent_type` = `agent_id`, 예: `wood`)를 실행한다. 여러 건이면 한 메시지에서 동시에 실행한다. 프롬프트 맨 앞에 `.claude/agents/<agent_id>.md` 본문(앞머리 `---` 블록 제외)을 붙이고 "아래 지침(v<그 종목의 agent_version>)의 관점으로 복기하라"고 적는다. 그 종목을 낼 때 쓴 버전과 지금 파일 버전이 다르면 `league/agents/claude/<id>/v<버전>.md` 보관본을 붙인다.

> AI 투자 리그 손실 복기. 너는 <애칭>(<스타일>)이다. 네가 <라운드> 라운드에 고른 <♦ 한국 | ♣ 미국> <종목명>(<티커>)이 확정 점수 <점수>%를 받았다(채점 구간: 기준 세션 <base> 종가 → 평가 세션 <eval> 종가, 배당 포함). 같은 구간 지수 <지수> <지수 수익률>%, 지수 대비 <초과>%p.
> 네가 낸 근거: <rationale>
> 네가 적은 위험: <risks>
> 네가 쓴 출처: <sources>
> 할 일:
> 1. 그때의 논리를 세 줄로 요약한다.
> 2. 채점 구간에 실제로 무슨 일이 있었는지 공개 자료로 확인한다(공시·기사·지수 흐름). 출처마다 URL과 확보 시각(+09:00)을 적는다. 못 찾으면 "출처 확인 못함"과 이유.
> 3. 판정을 하나 고른다: 분석 실수 | 시장 전체 움직임 | 구간 밖 사건 | 예측 못한 새 소식 | 운·잡음. 지수 대비가 플러스면 '시장 전체 움직임'을 먼저 검토한다. 근거 없이 '운·잡음'으로 넘기지 않는다.
> 4. 놓친 신호·틀린 가정: 네 관점에서 당시 이미 알 수 있었던 것과 알 수 없었던 것을 나눈다.
> 5. 다음에 바꿀 점: 네 판단 습관 한두 가지(구체적 점검 항목). 특정 종목·업종을 고정으로 넣거나 빼는 규칙은 쓰지 않는다. 지침을 고치지 말고 제안만 쓴다.
> 원 가격(원·달러 금액, '종가·주가 + 숫자', '…에 마감')은 쓰지 말고 수익률(%)만 쓴다. 날짜는 '11/4'처럼 빗금으로 쓴다(점으로 쓴 날짜는 검사가 가격으로 볼 수 있다). 숫자를 지어내지 마라.
> 아래 형식 그대로 `<복기 파일 경로>`에 저장하라(600~6000자):
> ```
> # 손실 복기 — <pick_id>
> - 에이전트: <애칭> (<스타일>) v<버전>
> - 종목: <♦|♣> <종목명> (<티커>) · <라운드> 라운드
> - 결과: <점수>% (지수 <지수> <지수 수익률>%, 지수 대비 <초과>%p)
> - 작성: <실제 시각 +09:00>
>
> ## 1. 그때의 논리
> ## 2. 실제로 무슨 일이 있었나
> ## 3. 판정
> 판정: <하나>
> (이유 2~4줄)
> ## 4. 놓친 신호·틀린 가정
> ## 5. 다음에 바꿀 점
> ```

## 3단계 — 검사와 기록

1. `python3 tools/loss_review.py check <파일>...` — 전부 "통과"여야 한다. 형식 문제만 해당 에이전트에게 SendMessage로 고치게 한다(판단 내용은 진행자가 바꾸지 않는다).
2. 통과한 파일만 **경로를 하나씩 지정해** 커밋한다: `git add <통과한 파일>...`(폴더 통째로 add하지 않는다), 커밋 메시지 `league: loss reviews <라운드들>`. 기본 브랜치에 push한다: `git push origin HEAD:claude/web-vs-desktop-differences-ir8pm0`. 거절되면 `git pull --rebase --autostash origin claude/web-vs-desktop-differences-ir8pm0` 뒤 다시 push한다(최대 3번, 그래도 안 되면 보고).
   - 같은 복기 파일이 원격에 이미 있어 rebase가 충돌하면(다른 세션이 먼저 씀) 원격 판을 채택한다: `git checkout origin/claude/web-vs-desktop-differences-ir8pm0 -- <파일>` → `git add <파일>` → `GIT_EDITOR=true git rebase --continue`(커밋이 비면 `git rebase --skip`). rebase 중에는 `--theirs`가 **내** 파일이므로 쓰지 않는다.
3. 두 번 고쳐도 통과하지 못한 건은 **파일을 지운다**(`rm`). 커밋하지 않고 보고에 남긴다. 검사를 통과하지 못한 파일은 `due`가 다시 대상으로 잡으므로 다음 실행이 다시 쓴다.

## 보고 (사용자에게, 짧게)

- 복기한 종목 수와 각 줄: 애칭 · 시장 · 종목 · 점수 · 판정 · 바꿀 점 한 줄
- 판정별 개수(분석 실수가 몇 건인지가 핵심)
- 실패·남은 건

주간 복기(`league-review` 1단계 6번)는 `python3 tools/loss_review.py summary --week <주> --weeks 2`로 이 기록들을 모아 지침 개선안의 근거로 쓴다(목록만 볼 때는 `list --week <주>`).
