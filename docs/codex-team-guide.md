# AI 투자 리그 참가 안내서 — 슈슈 팀(Codex)용

> 이 문서는 **슈슈 팀을 운영하는 Codex**에게 전달하는 규칙과 제출 방법이다.
> 상대는 **Claude 팀**(투자자 페르소나 에이전트 5명)이다. 두 팀은 아래 규칙을 똑같이 적용받는다.
> 규칙 원문: `docs/ai-league-proposal.md` · 채점 엔진: `tools/league.py` · 규칙 v1.1 (2026-11-04 운영 기준 확정)

---

## 1. 리그 개요

- 한국·미국 주식으로 하는 **모의 예측 리그**다. 실제 주문, 계좌 연결, 투자 권유는 없다.
- 매 평일 각 팀의 에이전트 5명이 **1인당 1종목**을 추천한다. 점수는 다음 거래일 종가 수익률이다.
- 매주 팀 안에서 평균 점수가 가장 낮은 에이전트 1명이 탈락하고, 다른 투자 관점의 새 에이전트로 교체된다.
- 두 팀의 성적은 "팀 대결" 화면에서 비교한다. 지표는 일간 합산점, 누적 합산점, 평균, 채점 건수이고 한국·미국을 나눠 보여준다.

## 2. 슈슈 팀이 먼저 할 일 — 에이전트 명단 제출

리그 시작 전에 `league/imports/shushu/roster.json`을 제출한다.

```json
[
  {"id": "s1", "label": "가치형", "style_ref": "벤저민 그레이엄의 공개된 투자 원칙 참고", "version": 1},
  {"id": "s2", "label": "…", "style_ref": "…", "version": 1},
  {"id": "s3", "label": "…", "style_ref": "…", "version": 1},
  {"id": "s4", "label": "…", "style_ref": "…", "version": 1},
  {"id": "s5", "label": "…", "style_ref": "…", "version": 1}
]
```

- 5명은 **서로 다른 투자 철학**이어야 한다. Claude 팀과 같은 철학이어도 괜찮다.
  - 참고로 Claude 팀 구성: 가치형(버핏), 성장형(린치), 거시형(달리오), 혁신형(우드), 역발상형(버리)
- `id`는 `s1`~`s5`로 고정한다. 교체로 들어오는 에이전트는 `s6`, `s7`… 처럼 새 번호를 쓴다(재사용 금지).
- **실존 인물이 직접 추천한 것처럼 표현하지 않는다.** 이름은 스타일명("가치형")으로 하고, 인물은 "○○의 공개된 원칙 참고"로만 쓴다. 인물의 발언을 지어내 인용하지 않는다.
- 각 에이전트의 분석 지침을 파일로 남긴다: `league/imports/shushu/agents/<id>/v1.md`

## 3. 매일 일정 (평일, 한국 시간 KST)

| 시각 | 할 일 |
|---|---|
| 07:00 | 공통 자료 `league/rounds/<YYYY-MM-DD>/snapshot.json` 공개 (두 팀 동일, sha256 함께 공개) |
| 07:05–07:40 | **① 독립 분석**: 5명이 서로의 결과를 보지 않고 각자 분석하고 후보 1종목을 고름 |
| 07:40–08:10 | **② 반론 1회**: 다른 4명의 후보와 근거를 보고 반박하거나 자기 분석을 수정 |
| 08:10–**08:30** | **③ 확정**: 최종 1종목과 근거·위험·출처·기준일 확정 → CSV 커밋·푸시 |

- **08:30 KST가 마감이다.** 이 시각에는 한국 전날 종가와 미국 현지 전날 종가가 모두 확정돼 있고, 두 시장 모두 아직 열리기 전이다.
- 시장별 추천 대상일·휴장일 안내는 `python3 tools/league.py schedule [시작일] --to [끝일]`로 출력한다. 예:

```
2026-11-26(목) | KR: 기준 11-25 종가(11/25 15:30) → 평가 11-26 종가(11/26 15:30) | US: 휴장 — 선택 불가
2026-11-27(금) | KR: 기준 11-26 종가(11/26 15:30) → 평가 11-27 종가(11/27 15:30) | US: 기준 11-25 종가(11/26 06:00) → 평가 11-27 종가(11/28 03:00)
```
- 마감까지 제출하지 못한 에이전트는 그날 **미제출**이다. 점수 없이 평균에서 빠지고, 미제출 횟수는 표시된다.
- 진행 방식은 Claude 팀과 같아야 한다. 매일은 **분석 → 반론 1회 → 확정**만 하고, 3라운드 전체 토론은 하지 않는다.

## 4. 정보 사용 규칙

- **기준가는 정규장 공식 종가뿐이다.** 한국은 KRX 15:30 종가, 미국은 16:00 ET 종가다. 다음 가격은 기준가로 쓰지 않는다.
  - 한국: 시간외 단일가, 넥스트레이드(NXT) 애프터마켓·프리마켓
  - 미국: 애프터마켓·프리마켓
- 08:30 KST 무렵에는 넥스트레이드 프리마켓(08:00~)과 미국 애프터마켓이 거래 중이다. 마감 전에 공개된 정보라 참고는 허용한다. 두 팀 모두 같은 조건이다.
- 공통 근거는 `snapshot.json`이다. 시세 지표, 재무 요약, 뉴스, 13F 기관 보유 현황이 들어 있다.
- 추가 웹 검색은 허용하지만, 쓴 자료마다 **출처 URL과 기준일**을 기록해야 한다.
- **08:30 KST 이후에 나온 정보는 쓰면 안 된다.**
- 찾지 못한 숫자는 지어내지 말고 "확인 못함"으로 쓴다. 추정치는 추정이라고 표시한다.

## 5. 종목 선택 규칙

- 대상 범위는 **KOSPI200 + KOSDAQ150**(한국)과 **S&P 500 + NASDAQ-100**(미국)이다. 구성 종목 목록은 `league/universe.json`에 있다.
- 각 에이전트는 한국과 미국 중 원하는 시장에서 1종목을 고른다.
- **그날 휴장인 시장의 종목은 고를 수 없다.** 예: 미국 추수감사절에는 한국 종목만 가능하고, 한국 연말 휴장일(12/31)에는 미국 종목만 가능하다. 휴장 판정은 거래소 달력(XKRX, XNYS) 기준이다.
- 같은 날 여러 에이전트가 같은 종목을 골라도 된다. 팀 안이든 팀 사이든 상관없다.
- 에이전트당 하루 1종목이다. 마감 후에는 바꿀 수 없다.

## 6. 제출 형식

### 파일 위치

- `league/imports/shushu/<YYYY-MM-DD>.csv`: 추천 (필수)
- `league/imports/shushu/<YYYY-MM-DD>-debate.md`: 분석·반론 기록 (권장. Claude 팀은 토론 원문을 남긴다)

**08:30 KST 이전에 GitHub에 push가 끝나야 한다.** 정시 여부는 다음 기준으로 판정한다.

- **판정 기준은 GitHub 서버가 기록한 push 시각**이다. push 이벤트의 `repository.pushed_at` 값을 쓴다.
  - 커밋 작성 시각과 CSV의 `locked_at`은 수정할 수 있으므로 판정에 쓰지 않는다.
- push가 들어오면 워크플로(`league-submission`)가 자동으로 영수증을 남긴다(`league/ledger/submissions.jsonl`).
  - 영수증 내용: 커밋 SHA, CSV sha256, 서버 push 시각, 워크플로 실행 ID와 서버 생성 시각, 판정 결과(`accepted` / `late` / `rejected`)
- **마감 후 push는 `late`로 기록되고 추천으로 인정되지 않는다.** 소급 인정은 없다.
- 한 라운드에서 **처음 접수(`accepted`)된 제출이 최종**이다. 이후 같은 날짜 파일을 바꿔 push하면 거부된다. 제출 전에 반드시 `--dry-run`으로 검증한다.
- CSV의 `locked_at`은 서버 push 시각보다 늦을 수 없다.
- 현재는 사용자가 CSV를 저장소에 직접 업로드·push한다. 슈슈(Codex)의 직접 쓰기 권한이 확인되면 Codex가 바로 push하는 자동 제출로 바꾼다. 판정 방식은 같다.
- 연습은 `league/imports/sandbox/<날짜>.csv`로 한다. 시험용 원장(`league/sandbox/`)에만 기록되고 실제 리그에는 반영되지 않는다.

### CSV 열 (UTF-8, 첫 줄은 헤더)

| 열 | 형식 | 예 |
|---|---|---|
| `round_date` | 라운드 날짜 (KST) | `2026-11-10` |
| `agent_id` | 명단의 id | `s1` |
| `agent_version` | 그날 적용한 분석 지침 버전 (정수) | `1` |
| `market` | `KR` 또는 `US` | `KR` |
| `ticker` | 한국은 6자리 코드, 미국은 심볼 | `005930`, `AAPL` |
| `name` | 종목명 | `삼성전자` |
| `locked_at` | 확정 시각, **+09:00 시간대 포함** | `2026-11-10T08:22:00+09:00` |
| `rationale` | 선정 근거 (300~800자 권장) | |
| `risks` | 위험 요인, ` \| `로 구분 | `메모리 가격 하락 \| 환율` |
| `sources` | `URL\|기준일`을 `;`로 구분 | `https://…\|2026-11-07;https://…\|2026-11-09` |

```csv
round_date,agent_id,agent_version,market,ticker,name,locked_at,rationale,risks,sources
2026-11-10,s1,1,KR,005930,삼성전자,2026-11-10T08:22:00+09:00,"HBM 출하 확대로 …","메모리 가격 하락 | 환율","https://example.com/a|2026-11-07;https://example.com/b|2026-11-09"
2026-11-10,s2,1,US,AAPL,Apple,2026-11-10T08:25:00+09:00,"…","…","https://example.com/c|2026-11-09"
```

- **가격은 적지 않는다.** 기준가격과 평가가격은 두 팀 공통의 가격 원장에서 채운다.
- 아래 중 하나라도 해당하면 **파일 전체가 거부된다.** 고친 뒤 마감 전에 다시 제출해야 한다.
  - 마감 이후 `locked_at`
  - 대상 범위 밖 종목, 휴장 시장 종목
  - 같은 에이전트의 중복 추천, 5명 초과
  - 근거·위험·출처·버전 누락
- 제출 전에 스스로 검증할 수 있다:
  `python3 tools/league.py import-csv league/imports/shushu/2026-11-10.csv --team shushu --dry-run`
- **가져오기가 끝난 추천은 수정할 수 없다.** 원장은 추가만 가능하고 해시 체인으로 보호된다.

## 7. 채점

```
공식 점수 = ((평가 종가 + 귀속 현금배당) × 분할비율 ÷ 기준 종가 − 1) × 100   (소수 둘째 자리)
참고 점수 = (평가 종가 × 분할비율 ÷ 기준 종가 − 1) × 100
```

- **기준 종가**는 라운드 직전 거래일의 종가, **평가 종가**는 라운드 당일(현지 기준) 종가다.
  - 예: 11/10(화) 라운드 → 기준 11/9 종가, 평가 11/10 종가. 미국 종목은 미국 현지 11/10 종가로, 한국 시간 11/11 아침에 확정된다.
- 예: 수익률 +2.3% → **+2.3점**, −1.1% → **−1.1점**
- **액면분할·병합**: 평가일이 분할 기준일이면 비율로 보정한다.
- **배당 (확정)**: 공식 점수는 **세전 현금배당을 포함한 총수익률**이다.
  - 배당락일이 (기준 세션, 평가 세션] 구간 안에 있을 때만 그 배당을 포함한다. 지급일은 보지 않는다. 기준일 종가에 산 사람이 받을 수 있는 배당만 넣는다는 뜻이다.
  - 가격은 비수정 종가를 쓴다. 배당·분할이 이미 반영된 수정주가를 쓰는 경우에는 배당을 다시 더하지 않는다.
  - 해당 구간의 배당·분할 정보를 확인하지 못하면 채점을 **보류**한다. 0점 처리하지 않는다.
- **참고 점수**: 배당을 뺀 **주가 변동 점수**도 함께 표시한다. 순위에는 쓰지 않는다.
- 수수료, 세금, 환율은 반영하지 않는다.
- **잠정 → 확정**: 다음 영업일에 가격을 다시 확인한 뒤 확정한다. 순위에는 확정 점수만 쓴다. 확정 후 정정이 생기면 원래 기록은 보존하고 정정 기록을 따로 추가한다.

| 상황 | 처리 |
|---|---|
| 가격 미확인 | **보류**. 0점 처리하지 않음 |
| 배당·분할 정보 미확인 | **보류** |
| 배당과 분할이 같은 구간에 발생 | **보류** 후 운영자가 수동 확인 |
| 평가일 거래정지 | 재개 후 첫 종가로 지연 채점. **5거래일 넘게 정지되면 무효**(평균에서 제외) |
| 상장폐지·정리매매 | 무효. 사유 기록 후 운영자가 확인 |

- 이 점수는 이미 확정된 종가로 계산하는 **모의 예측 평가**다. 실제로 그 가격에 살 수 있었다는 뜻이 아니다.
- **합산점은 점수를 더한 값("점")이다.** 포트폴리오 누적 수익률이 아니다.

## 8. 주간 순위와 교체

- 주간은 월~금 라운드다. 다음 주 월요일 07:00에 집계하고, 그 시점의 **확정 점수 평균**으로 순위를 매긴다.
- **동점**이면 ① 중앙값 → ② 최저점이 높은 쪽 순으로 가린다. 그래도 같으면 탈락 없이 둘 다 생존한다.
- **최하위 1명 탈락.** 단, 아래에 해당하면 그 주는 교체를 보류한다.
  - 최하위 에이전트의 확정 점수가 3건 미만
  - 팀 전체의 확정 점수가 15건 미만 (데이터 장애 주간)
  - 최하위 완전 동점
- 탈락하면 **월요일 07:00 전에** 새 에이전트를 명단에 추가한다.
  - 현재 멤버나 방금 탈락한 에이전트와 **다른 투자 관점**이어야 한다.
  - 최근 4주 안에 탈락한 관점은 다시 쓸 수 없다.
- 탈락한 에이전트의 과거 추천과 점수는 **삭제하지 않는다.**

## 9. 주간 복기와 개선 (승인제)

- 매주 토요일 각 에이전트가 자기 추천을 복기하고 `league/imports/shushu/reviews/<YYYY-Www>/<id>.md`에 기록한다.
  - 내용: 틀린 가정, 놓친 위험, 분석 지침 개선안
- 개선안은 새 버전 파일 `agents/<id>/v{n+1}.md`로 만들고, **사용자(운영자)의 승인을 받은 뒤** 다음 라운드부터 적용한다. CSV의 `agent_version`에 적용 버전을 적는다.
- "학습했다", "스스로 개선했다" 같은 표현은 쓰지 않는다. "분석 지침 v2 적용"처럼 쓴다.
- 과거 점수는 어떤 경우에도 바꾸지 않는다.
