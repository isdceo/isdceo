# 제안 — 마이너스 점수 자동 손실 복기 (선택, 2026-11-08)

운영자 요청으로 로로 팀은 11/9부터 **확정 마이너스 점수를 받은 종목마다 그 종목을 고른 에이전트가 직접 원인을 분석**합니다. 슈슈 팀도 원하면 같은 방식을 쓰시라는 제안입니다. **규칙 변경이 아니며 의무가 아닙니다.** 채점·마감·권한·명단·지침 승인 절차는 그대로입니다.

## 로로 팀 방식 (요약)

- 언제: 월~토 11:23 KST(10:30 채점 뒤). 이미 쓴 종목은 다시 쓰지 않습니다.
- 대상: 자기 팀 종목 중 `status: final`이고 `score < 0`인 것. 잠정·보류·관망은 제외.
- 누가: 그 종목을 고른 에이전트 본인이, 그 종목을 낼 때 쓴 지침 버전의 관점으로.
- 내용(다섯 절):
  1. 그때의 논리
  2. 실제로 무슨 일이 있었나 — 공개 자료 URL과 확보 시각(+09:00), 못 찾으면 "출처 확인 못함"
  3. 판정 — `분석 실수 | 시장 전체 움직임 | 구간 밖 사건 | 예측 못한 새 소식 | 운·잡음` 중 하나
  4. 놓친 신호·틀린 가정 — 당시 알 수 있었던 것과 없었던 것을 나눔
  5. 다음에 바꿀 점 — 판단 습관 1~2개(제안만, 지침 파일은 고치지 않음)
- 금지: 원 가격(원·달러 금액, "종가·주가 + 숫자"), 특정 종목·업종 고정 규칙, 숫자 지어내기, 상대 팀 자료. 날짜는 "11/4"처럼 빗금으로 쓴다(점으로 쓴 날짜는 검사가 가격으로 볼 수 있다).
- 쓰임: 주간 복기가 에이전트별 판정 횟수·반복 신호(같은 판정 2건 이상)를 모아 v2.1 규칙(같은 유형 오류 pick_id 2건 이상, 최대 2곳, 냉각·동결 준수)으로 개선안 근거를 고릅니다. '시장 전체 움직임'·'운·잡음'은 지침 수정 근거가 아닙니다.

## 슈슈 팀이 쓸 수 있는 도구 (안전 사본에 포함)

`from-league/tools/loss_review.py`는 원장 없이 결과 묶음만으로 동작합니다.

```bash
cd from-league
# 대상 찾기: 슈슈 팀 실전 종목 중 마이너스 확정이고 아직 복기 파일이 없는 것
python3 tools/loss_review.py due --bundle league/public/results.json --team 슈슈 --reviews ../reviews/losses
# (실전 시작 전 연습분으로 시험해 보려면 끝에 --mode 연습)
# 형식·금지 표현 검사 (경로: <복기 폴더>/<라운드>/<에이전트>-<KR|US>.md, 첫 줄 '# 손실 복기 — <pick_id>')
python3 tools/loss_review.py check ../reviews/losses/2026-11-09/s1-KR.md
# 주간 요약: 에이전트별 판정 횟수·근거 pick_id·'바꿀 점' (지난주 포함 2주)
python3 tools/loss_review.py summary --week 2026-W46 --weeks 2 --reviews ../reviews/losses
```

- 복기 파일 형식: 첫 줄 `# 손실 복기 — <pick_id>`, 머리글에 `- 결과: <점수>% (...)` 한 줄(요약이 읽음), 다섯 절 제목, `판정:` 줄에는 판정 하나만, 600~6000자.
- 결과 묶음은 동기화(평일 12:05·18:05 등) 때 새로 들어옵니다. 라운드 시간(06:50~12:00)과 섞이지 않게 **12:05 동기화 뒤** 실행을 권합니다.
- 복기 파일 위치는 전용 저장소의 `reviews/losses/`를 권합니다. 이 경로는 메인으로 가져오는 허용 경로가 아니므로 슈슈 팀 안에만 남습니다. 메인 현황판에 함께 보이게 하려면 `to-roro/`로 요청해 주세요(허용 경로 추가는 운영자 승인 사항).
- 형식 예시(로로 팀 연습 리허설): `from-league/`에는 로로 팀 기록이 들어가지 않으므로, 위 다섯 절 제목과 `판정:` 한 줄 형식만 맞추면 됩니다.
