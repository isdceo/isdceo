# 슈슈 팀 주간 복기 절차 추가안

작성일: 2026-11-07  
적용 규칙: 리그 v2.1  
첫 대상 주: 2026-W46, 2026-11-09~2026-11-15  
첫 복기: 2026-11-14 토요일 10:30 KST 채점 뒤  
첫 최종 확인: 2026-11-16 월요일 06:30 KST 주간 마감 뒤  
시간 기준: 모두 한국 표준시 KST

## 1 적용 범위와 현재 상태

이 별첨은 슈슈 팀의 주간 복기에서 지침 업데이트 대상을 확인하고, 반복된 판단 오류에 근거한 소규모 변경을 승인받는 절차를 정리한다. 기존 절차서에 덧붙일 새 문서이며, 기존 원본이나 운영 저장소를 수정한 것은 아니다.

현재는 절차 준비 단계다. 11월 14일 점수, 실제 `pick_id`, 업데이트 대상, 개선 지침, 승인 및 적용 결과는 아직 없다. 아래 양식은 해당 자료가 생긴 뒤 작성한다. 이 문서에 적힌 명령은 실행하지 않았으며, 실제 구현과 명단의 반영 여부도 확인하지 않았다.

v2.1은 v2.0의 시장별 리그 운영에 추가되는 지침 변경 규칙이다. 시장별 참가 자격과 교체는 운영자의 주간 마감 기록을 따르고, 이 절차로 복귀나 참가 자격을 만들지 않는다.

## 2 업데이트 대상과 금지 조건

| 확인 조건 | 처리 |
|---|---|
| 한국 또는 미국 중 어느 한 리그에서 1등, 공동 1등 포함 | `frozen`. 해당 에이전트의 지침 전체를 이번 복기에서 동결한다. 다른 시장에서 2~9등이어도 수정하지 않는다. |
| 두 리그 모두 탈락 | `out`. 지침을 업데이트하지 않는다. |
| 해당 주 추천에 새 `agent_version`이 기록되어 냉각 기간에 해당 | `cooldown`. 이번 마감에서 다시 수정하지 않는다. |
| 위 금지 조건이 없고 최종 상태가 `eligible` | 같은 유형의 판단 오류가 서로 다른 `pick_id` 2건 이상에서 확인될 때만 소규모 개선안을 검토한다. |
| 순위·마감·버전 이력 중 필요한 정보가 없거나 공지와 출력이 불일치 | 적용을 보류하고 운영자 확인을 받는다. 근거 없이 `eligible`로 간주하지 않는다. |

- 한 시장에서만 탈락했더라도 남은 시장의 순위와 최종 상태에 따라 검토 대상이 될 수 있다.
- `eligible`은 변경 의무나 승인 완료를 뜻하지 않는다. 반복 오류 근거가 부족하면 기존 지침을 유지한다.
- 여러 금지 조건이 겹치면 모두 기록하고 업데이트하지 않는다. 출력 상태명 간 우선순위는 실제 `update-plan` 결과와 운영자 확인을 따른다.
- 한 시장의 1등 동결은 에이전트 단위다. 다른 시장 부분만 고치는 방식으로 우회하지 않는다.

## 3 변경안 작성 기준

### 반복 오류를 먼저 확인한다

1. 결과 수익률과 당시 판단 과정을 분리한다. 손실, 낮은 주간 순위, 특정 종목의 사후 급등락만으로 판단 오류라고 결론 내리지 않는다.
2. 당시 제출된 근거와 마감 전에 확보한 자료를 읽고, 어떤 확인이나 추론이 잘못되었는지 적는다. 사후 자료를 당시 알 수 있었던 정보처럼 사용하지 않는다.
3. 같은 오류 유형을 뒷받침하는 서로 다른 `pick_id`를 최소 2건 연결한다. 한 추천의 사실 주장 2개, 같은 추천의 중복 기록, 정정본을 각각 별도 추천으로 세지 않는다.
4. 각 근거에 시장, 라운드 날짜, 당시 `agent_version`, 원래 판단, 확인 자료와 확보 시각을 남긴다. 오류라고 보기 어려운 반례와 표본 부족도 함께 적는다.
5. 원자료 정정이나 채점 대기는 판단 오류와 별도로 기록한다. 점수 수정만으로 지침 수정이 필요하다고 간주하지 않는다.

### 최대 두 곳만 바꾼다

- 에이전트별 한 번의 업데이트에서 지침을 최대 2곳만 바꾼다.
- 변경 위치와 변경 전후 문장을 나란히 적고, 각 변경 사유에 반복 오류 근거를 연결한다.
- 투자 스타일과 캐릭터는 유지한다.
- 특정 종목이나 업종을 고정으로 넣거나 빼지 않는다.
- 결과 하나에 맞춘 기준이나, 지난 결과에 맞게 숫자를 조정한 기준을 추가하지 않는다.
- 여러 독립 변경을 한 문단에 묶어 변경 수를 줄여 세지 않는다. 2곳을 넘는 수정은 이번 안에 포함하지 않는다.
- 실제 변경안이 없으면 버전 번호만 올리지 않는다. 기존 승인 버전을 유지한다.

이 기준은 사후 성과에 맞춰 지침을 과도하게 조정하는 것을 막기 위한 것이다. 소규모 표본의 성적 개선을 재현 가능한 효과나 투자 능력 향상으로 단정하지 않는다.

## 4 토요일 잠정 복기

첫 실행일은 2026-11-14 토요일이다.

1. 10:30 채점 뒤 자료를 확보하고, 확보 시각과 자료 버전을 기록한다.
2. 한국과 미국을 분리해 주간 순위, 확정·제출·기대·미제출·채점 전·보류 건수를 기록한다. 누적 성적도 표본 수와 함께 참고한다.
3. 개별 점수는 자료의 실제 상태에 따라 확정·잠정·채점 전·보류로 표시한다. 확정되지 않은 값은 0점으로 채우지 않는다.
4. 토요일 복기 전체에는 **주간 마감 전 잠정 복기**라고 표시한다. 개별 점수가 확정되어 있어도 월요일의 최종 업데이트 자격까지 확정된 것은 아니다.
5. 다음 명령의 출력과 이유를 보관한다.

```bash
python3 tools/league.py update-plan 2026-W46
```

6. 토요일에 아직 주간 마감 기록이 없어 출력이 없거나 명령이 실패하면, 그 사실을 남긴다. 잠정 순위로 공식 `eligible` 상태를 만들어 적지 않는다.
7. 토요일에 `eligible`로 표시된 경우에도 개선안은 **잠정 검토안**으로 작성한다. 출력이 없는 경우에는 오류 근거만 정리하고 적용 여부는 월요일까지 보류한다.
8. 에이전트마다 근거의 사실 주장 2~3개를 원문과 대조해 근거 정확도를 기록한다. 이 참고 감사 결과를 점수나 순위에 합산하지 않는다. 감사에서 확인된 오류도 지침 변경에 쓰려면 서로 다른 `pick_id` 2건 이상 요건을 충족해야 한다.
9. 최초 복기와 근거를 보존한다. 이후 점수·순위·자격이 바뀌면 원문을 덮어쓰지 않고 보완 기록을 추가한다.

## 5 월요일 최종 확인과 승인

첫 실행일은 2026-11-16 월요일이다.

### 06시 30분 주간 마감 뒤

1. 대상 주가 2026-W46인지 확인하고, 운영자의 한국·미국 주간 마감 기록과 시장별 참가 자격을 읽는다.
2. 같은 `update-plan` 명령을 다시 실행해 최종 상태와 이유를 저장한다.
3. 토요일 기록과 차이를 확인한다. 공동 1등 동결, 냉각 기간, 양 시장 탈락 등으로 대상에서 빠졌다면 개선안을 **적용 대상에서 철회**한다.
4. 철회한 안은 감사 기록으로 보존하고 철회 이유를 덧붙인다. 토요일 복기에서 지우거나 승인된 지침으로 사용하지 않는다.
5. 최종 `eligible`인 에이전트만 근거 2건 이상, 변경 최대 2곳, 스타일·캐릭터 유지 여부를 다시 확인한다.
6. 승인 요청 묶음을 운영자에게 전달할 수 있도록 준비한다. 전달과 승인은 별도 단계이며, 답이 없다는 이유로 승인으로 처리하지 않는다.

### 승인과 적용

- 월요일 07:05 **전** 운영자 승인을 받은 변경은 그날 라운드부터 적용한다.
- 07:05 또는 그 이후 승인, 승인 시각 불명확, 적용 라운드 미확정, 필요한 파일 미반영은 **적용 대기**로 기록한다. 승인 뒤 첫 적용 라운드를 운영자와 확인할 때까지 현재 승인 버전을 유지한다.
- 07:05 이후 승인에서 당일 라운드도 포함되는지는 아래 확인 사항에 따른다. 임의로 당일 적용을 확정하지 않는다.
- 승인된 버전별 지침 파일, 슈슈 팀 명단의 `version`, 추천 CSV의 `agent_version`을 일치시킨다. 버전이 다르면 제출이 거부되므로 추측해 입력하지 않는다.
- 승인 여부, 승인 시각, 적용 라운드, 지침 파일, 명단 버전을 함께 기록한다.
- 제출 전 기존 검증 절차로 CSV를 확인한다. 이 별첨은 지문 08:30 전 제출 및 원본 08:30~12:00 공개 절차를 바꾸지 않는다.
- 지문을 만든 뒤에는 버전 변경을 이유로 CSV를 수정하지 않는다. 이미 동결된 원본은 그대로 보존하고, 새 버전의 적용 라운드는 운영자와 다시 확인한다.

‘잠정 검토안’, ‘승인 대기’, ‘적용 대기’, ‘철회’는 이 절차의 작업 상태다. `update-plan`이 반환하는 네 가지 공식 상태명과 구분해 기록한다.

## 6 승인 요청 묶음

실제 개선안이 있을 때 다음 자료를 한 묶음으로 준비한다.

1. 대상 주와 에이전트 ID, 기존 승인 버전 및 요청 버전.
2. 한국·미국 최종 순위와 참가 자격, 최종 `update-plan` 상태·이유·확인 시각.
3. 같은 오류 유형을 입증하는 서로 다른 `pick_id` 2건 이상과 원문 근거.
4. 변경 위치별 전후 문장. 총 변경 수는 0~2곳으로 명시한다.
5. 투자 스타일과 캐릭터가 유지되는 이유, 기대하는 판단 과정 개선, 부작용과 남은 불확실성.
6. 새 버전 지침 파일과 명단 `version` 변경안.
7. 운영자 승인란과 적용 라운드. 승인 전에는 비워 둔다.

새 파일명은 기존 버전별 지침의 명명 규칙을 따른다. 이전 지침은 과거 추천의 재현을 위해 보존하고, 당시 추천의 `agent_version`을 소급 수정하지 않는다.

## 8 운영자 확인이 필요한 사항

v2.1의 핵심 기준은 반영했지만, 다음은 실제 적용 전에 확인해야 한다. 의견 회신 기한은 2026-11-13 금요일 18:00 KST다.

1. **토요일 상태 조회 방식**  
   순위 기준은 주간 마감 기록인데 첫 복기는 마감 전인 11월 14일이다. `update-plan`이 토요일에도 잠정 결과를 반환하는지, 아니면 월요일 마감 뒤에만 상태를 반환하는지 확인이 필요하다. 답변 전에는 토요일 자격을 확정하지 않는다.

2. **첫 주 v1과 냉각 기간**  
   ‘그 주에 새 버전 추천이 있으면 cooldown’에서 시즌 최초 v1도 새 버전으로 보는지, 기존 버전에서 올라간 경우만 뜻하는지 명확히 해야 한다. 최초 합류 에이전트와 주중 버전 변경의 판정도 같은 기준으로 확인한다. 파일 생성일이나 승인일만으로 냉각 기간을 추정하지 않고 실제 추천의 `agent_version` 이력을 사용한다.

3. **07시 05분 이후 승인**  
   공지는 늦으면 ‘승인 뒤 첫 라운드부터’라고 한다. 월요일 분석 시작 뒤 승인되어도 월요일 라운드가 가능한지, 다음 라운드로 넘기는지 확인이 필요하다. 07:05 정각은 ‘전’에 포함하지 않는다. 확인 전에는 현재 승인 버전으로 유지한다.

4. **두 시장을 함께 쓰는 버전의 범위**  
   공지상 한 시장 1등이면 에이전트 전체 동결로 처리한다. 한 시장에서만 탈락한 에이전트의 명단 버전과 남은 시장 CSV 버전을 어떻게 함께 관리하는지 실제 명단·검증 결과로 확인한다. 한 시장만 고쳐 1등 동결을 우회하지 않는다.
