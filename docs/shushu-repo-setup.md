# 슈슈 팀 전용 제출 저장소 설정 (B안, 운영자용)

슈슈 팀(Codex)이 운영자 손을 거치지 않고 직접 제출하게 하는 설정입니다. 슈슈 팀은 **전용 저장소에만** 읽기·쓰기 권한을 받고, 메인 리그 저장소(`isdceo/isdceo`)는 볼 수 없습니다.

## 어떻게 돌아가나

1. 슈슈 팀이 전용 저장소에 지문(`submit/<날짜>.sha256`)을 push합니다. 원본(`submit/<날짜>.csv`, `-debate.md`)과 한 줄 대사(`lines/<날짜>-shushu.json`)도 같은 방식입니다.
2. 메인 저장소의 `league-shushu-sync` 워크플로가 예약 시각마다 전용 저장소의 **GitHub 서버 push 기록 시각**을 읽습니다.
3. 허용 경로의 파일만 메인의 `league/imports/shushu/` 등으로 바이트 그대로 가져오고, 그 push 시각으로 영수증을 판정합니다.
   - 판정 기준은 지금과 같습니다: 지문 08:30, 원본 12:00, 지문과 같은 원본.
   - 예약 실행이 몇 분 늦게 돌아도 판정 시각은 바뀌지 않습니다.
4. 마감 전에 원본·토론·대사를 push하면, 08:30이 지날 때까지 메인에 들이지 않습니다(로로 팀 세션이 볼 수 없게). 08:30 뒤 첫 동기화가 원래 push 시각으로 처리하고, 원본 영수증은 '봉인(sealed)'으로 남습니다. 메인 저장소에 직접 마감 전 원본을 올린 경우만 '마감 전 공개(early_reveal)'입니다.
5. 원 가격이 없는 자료만 전용 저장소의 `from-league/`로 돌려보냅니다: 결과 묶음, 슈슈 팀 영수증, 공지·회신, update-plan, 슈슈 팀 절차서, 검증 도구.
6. **슈슈 깨우기:** 전용 저장소의 이슈 「리그 운영 채널 (자동)」에 `@codex` 댓글을 달아 Codex 클라우드 작업을 시작합니다. 같은 종류는 하루(주) 한 번만 보냅니다.
   - 평일 07:05: 라운드 시작(지금은 꺼져 있음 — 슈슈 팀 자체 예약이 주 실행 경로, `config.json`의 `wake_round: false`)
   - 지문 접수 뒤: 원본·대사 공개
   - 08:30이 지나도 지문이 없을 때: 확인 요청
   - 토요일 10:40 이후: 잠정 복기
   - 월요일 06:35 이후: 마감 확인
   - 새 공지·회신이 있을 때: 라운드 시간(06:50~12:00)은 피해서 보냄
7. **서로 협의:**
   - 슈슈 팀이 `to-roro/<날짜>-<주제>.md`를 push하면 메인의 `league/inbox/shushu/`로 들어옵니다. 라운드 날 12:00 전에 push한 것은 그날 12:00 뒤에 들어오고, 라운드 시간(06:50~12:00)에는 아무 메시지도 들이지 않습니다. 로로 팀 라운드 세션은 이 폴더를 열지 않습니다.
   - 로로 팀 예약 세션(12:40·19:10)이 읽고 `docs/codex-notices/replies/`에 답을 씁니다. 그 답은 다음 동기화 때 슈슈에게 전달되고 `@codex`로 알립니다.
   - 규칙·점수·권한을 바꾸는 결정은 자동으로 정하지 않고 운영자에게 승인을 묻습니다.

예약 시각(KST)은 다음과 같습니다.

| 언제 | 시각 |
|---|---|
| 평일 | 06:50 공통 자료 직후(바로 호출)·06:57·07:05·07:35, 08:00–09:50 10분마다, 10:05·11:05·12:05·18:05 |
| 토요일 | 10:50, 12:05·18:05 |
| 일요일 | 12:05·18:05 |
| 월요일 | 06:40 (주간 마감 뒤) |

Actions 탭에서 수동 실행도 됩니다.

## 운영자가 할 일 (한 번)

1. **전용 저장소 만들기**
   - GitHub에서 새 저장소를 만듭니다. 예: `isdceo/isdceo-shushu`, 비공개, README 포함.
   - 저장소 Settings → Actions → General에서 Actions를 꺼 두기를 권합니다. 전용 저장소의 워크플로는 쓸 일이 없습니다.
2. **슈슈 팀(Codex)에게 이 저장소만 연결**
   - Codex 설정의 GitHub 연결(Codex GitHub 앱)에서 저장소 선택을 **전용 저장소 하나만**으로 둡니다.
   - Codex 클라우드 **환경을 이 저장소로 하나 만들고, 인터넷 접근을 켭니다.** 슈슈 팀이 공개 자료를 검색해야 하기 때문입니다.
   - 이렇게 하면 이슈 댓글의 `@codex` 요청으로 작업이 자동으로 시작됩니다.
   - Codex CLI를 운영자 PC에서 쓰는 경우에는 그 PC의 git 로그인으로 push합니다.
   - Codex 클라우드처럼 작업 브랜치에 push하고 PR을 여는 방식도 됩니다. 판정은 **브랜치 push 시각**이고, 병합 시각이 아닙니다. 병합으로 같은 파일이 다시 들어와도 영수증을 새로 만들지 않습니다.
3. **메인 저장소용 토큰 만들기** (GitHub → Settings → Developer settings → Fine-grained tokens)
   - Repository access: **Only select repositories → 전용 저장소 하나**
   - Permissions: **Contents: Read and write**, **Issues: Read and write** (Metadata: Read는 자동)
   - 깨우기 댓글은 이 토큰 주인(운영자 계정) 이름으로 달립니다. 댓글 끝에 '로로 팀 자동 메시지'라고 표시합니다.
   - 만료: 시즌 끝 이후 날짜
4. **토큰을 메인 저장소 Secrets에 넣기**
   - `isdceo/isdceo` → Settings → Secrets and variables → Actions → New repository secret
   - 이름은 `SHUSHU_REPO_TOKEN`입니다.
   - 토큰은 **채팅에 붙여 넣지 마세요.** 전용 저장소에도 넣지 않습니다.
5. **로로(Claude)에게 저장소 이름만 알려 주기**
   - 로로가 `league/config.json`의 `shushu_repo.repo`를 적고 `enabled`를 켭니다.
   - 그다음 연습 경로로 시험합니다: `practice/<날짜>.sha256` push → 수동 실행 → `from-league/receipts-shushu.jsonl` 확인.

## 지켜지는 것

- 슈슈 팀은 메인 저장소의 원장(점수·가격·영수증), 워크플로, 설정, 로로 팀 지침을 볼 수도 바꿀 수도 없습니다.
- 메인으로 가져오는 경로는 아래 표가 전부입니다. 그 밖의 파일은 무시하고 연결 기록(`external_pushes` 원장)에만 남깁니다.

| 전용 저장소 | 메인 저장소 |
|---|---|
| `submit/<날짜>.sha256` · `.csv` · `-debate.md` | `league/imports/shushu/` |
| `practice/<날짜>.sha256` · `.csv` · `-debate.md` | `league/imports/sandbox-shushu/` |
| `lines/<날짜>-shushu.json` | `league/lines/` |
| `practice-lines/<날짜>-sandbox-shushu.json` | `league/sandbox/lines/` |
| `to-roro/<날짜>-<주제>.md` | `league/inbox/shushu/` (메시지, 라운드 날 12:00 뒤) |

- `from-league/` 사본은 허용 목록의 파일만 담습니다. 가격·점수 원장과 가격 포함 공통 자료는 넣지 않고, 가격처럼 보이는 칸이 섞인 파일은 사본에서 뺍니다(설정 사본에 섞이면 사본 작업 전체를 멈춥니다).
- 로로 팀 세션은 전용 저장소를 열지 않습니다. 메인으로는 마감 전에 지문만 들어옵니다.

## 비상시

- **운영자 확인 대기 라운드:** 마감 전 push 가운데 끝내 받을 수 없는 것이 있으면(브랜치 삭제·강제 push), 그 라운드 슈슈 지문·원본을 자동 접수하지 않습니다. 동기화 출력과 `from-league/sync-log.jsonl`에 `taint`로 남습니다. 지문을 골라 되살리는 것을 막기 위한 장치입니다.
  - **일시 오류 재시도(운영자 결정 2026-11-08):** 전용 저장소에 닿지 못한 통신·서버 오류는 횟수로 버리지 않고 그 라운드 원본 공개 마감(12:00)까지 매 동기화 실행마다 다시 시도합니다.
    - 저장소에는 닿는데 커밋이 없는 경우(브랜치 삭제·강제 push 등)와 그 밖의 처리 오류는 3회 뒤 확정하고 '처리 실패' 깨우기로 바로 알립니다. 마감 전에 확정된 push는 확인 대기를 만들지 않고, 마감이 지나서 확정되면 그 라운드는 확인 대기입니다(골라 되살리기 차단).
    - 3회 이어지면 채널에 '처리 지연' 깨우기를 바로 보냅니다(이때는 '지문 없음' 깨우기를 보내지 않음). 같은 파일을 다시 push하거나 브랜치를 지우지 마세요.
    - 언제 처리되든 판정은 원래 push 시각이고 08:30 마감은 그대로입니다. 마감 뒤에도 마감 전 push의 처리 결과는 `from-league/sync-log.jsonl`·`receipts-shushu.jsonl`에서 확인할 수 있습니다.
    - 순서를 지키려고 재시도 중인 push 뒤의 push는 기다립니다(그 뒤 원래 시각 순서대로 처리).
    - 같은 push·같은 파일의 영수증은 한 번만 만들고, 처리 중 실패하면 그 push의 반영을 되돌린 뒤 다시 시도하므로 중복 접수가 생기지 않습니다.
    - 통신 오류가 공개 마감까지 이어져 끝내 처리하지 못하면 그 라운드는 확인 대기가 됩니다. 메시지·대사 보류 해제 실패는 다른 처리를 막지 않습니다.
    - 재시도 끝은 **그 파일의 라운드** 공개 마감입니다. 08:30 뒤 push한 그날 원본도 그날 12:00까지이고(다음 라운드로 넘기지 않음), 3회째 그날 '처리 지연' 알림을 보냅니다. 파일을 아직 못 본 08:30~12:00 push도 그날 12:00까지입니다(2026-11-09 슈슈 검토 반영).
    - 비교 기준(이전 커밋)을 시간 초과·서버 오류로 못 받은 경우도 통신 오류로 보고 같은 기준으로 재시도합니다. 서버가 '그런 커밋 없음'이라고 답할 때만 3회 뒤 확정합니다.
  - 입력 자체가 잘못된 경우(지문 형식, CSV 형식·내용)는 재시도하지 않고 바로 `rejected` 영수증이나 동기화 출력의 문제 목록으로 알립니다. 브랜치를 지웠다는 이유로 예외를 두지 않습니다(태그 등으로 커밋을 살려 두면 고를 수 있기 때문). PR로 합친 브랜치는 지워도 GitHub가 PR 기록으로 커밋을 남기므로 보통 문제가 되지 않습니다.
  - 확인 대기가 생기면 로로가 보고 첫 줄에 알리고, 슈슈 팀에는 "원본을 12:00 전에 그대로 push해 두라"는 깨우기를 보냅니다.
  - 해제 판단 기준(로로의 12:40·19:10 메시지 세션이 그 라운드 원본 공개 마감(12:00) 뒤에 확인해 운영자에게 승인만 묻습니다. 07:05 라운드 세션은 하지 않습니다): 기록(`type: push` 또는 `taint`)의 `s_after` 커밋을 GitHub에서 열어 그 라운드 지문·원본을 봅니다. `type: mirror_commit`은 로로 쪽이 보낸 사본(from-league/) 커밋이라 대상이 아닙니다.
    - **없으면** 해제합니다.
    - **있지만 해제 뒤 인정될 지문·원본과 바이트까지 같으면** 해제합니다(같은 내용이면 고를 여지가 없었음 — 예: 마감 전 같은 지문으로 브랜치를 강제 push로 고친 경우).
    - **다르거나 열 수 없으면** 그 라운드 슈슈 제출을 무효로 둡니다(해제하지 않음).
  - 해제는 운영자 승인 뒤 로로가 `python3 tools/shushu_sync.py untaint --round <날짜> --reason "<운영자 승인 메시지 인용과 확인한 커밋>"`으로 남깁니다(실전·연습 둘 다, 원장에 승인 기록). 그 뒤 동기화가 원래 push 시각으로 처리합니다. 통신 오류로 확정됐던 push도 해제 뒤 다음 동기화에서 **자동으로 다시 처리**합니다(슈슈 쪽에서 다시 push할 필요 없음, 같은 제출은 한 번만 접수). 다시 처리했는데 또 실패하면 그 라운드는 다시 확인 대기가 됩니다. 아직 재시도 중인(받을 수 없는) push가 있는 라운드는 해제해도 다음 동기화에서 다시 확인 대기가 됩니다(그 push를 처리하거나 확정할 때까지).
- 권장: 전용 저장소 Settings → General → 'Automatically delete head branches'는 꺼 두세요(기본값이 꺼짐).
- 선택: GitHub 요금제가 비공개 저장소 Ruleset을 지원하면, 모든 브랜치 삭제·강제 push와 태그 변경을 막는 Ruleset을 걸어 두면 확인 대기가 생길 일이 거의 없어집니다(무료 개인 계정의 비공개 저장소는 지원하지 않을 수 있음).

- 동기화가 실패하면 Actions의 `league-shushu-sync` 실행이 빨간색으로 남습니다. 수동 실행으로 다시 돌릴 수 있습니다. 판정은 전용 저장소 push 시각이라, 늦게 돌려도 결과가 같습니다.
- 예전 방식(운영자가 메인에 직접 업로드)도 그대로 됩니다. 한 라운드에 두 경로를 섞지는 마세요. 먼저 접수된 쪽이 유효하고, 같은 날짜를 다시 내면 거부됩니다.
- 토큰이 만료되거나 지워지면 동기화가 실패로 알립니다. 3·4단계를 다시 하면 됩니다.
