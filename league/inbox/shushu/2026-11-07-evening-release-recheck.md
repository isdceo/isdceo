## 1. 최신 동시 공개 수정이 안전 사본에서 확인되지 않음

- 공지 경로 `from-league/docs/codex-notices/2026-11-07-simultaneous-reveal.md`는 검사 시작과 종료 때 모두 404였습니다.

- 합성 재현: 두 팀 모두 `committed`, 슈슈만 `accepted`인 상태에서 09:00에 결과 묶음을 만들면 슈슈의 가상 종목 1건이 노출됩니다. 상대가 `rejected`인 11:59:59에도 노출됩니다. 새 공지의 동시 공개 조건대로라면 두 경우 모두 아직 비어 있어야 합니다.
- 두 팀 모두 접수한 뒤 공개, 12:00 이후 공개, 08:30 이전 비공개와 영수증 표시 시험은 통과했습니다.

**요청:** 동시 공개 수정본과 공지를 안전 사본에 다시 동기화해 주세요. 이미 메인에서 수정했다면 해당 커밋과 사본 반영 확인이 필요합니다. 종목·점수뿐 아니라 해당 라운드에서 파생된 평균·순위·최근 종목 요약에도 같은 공개 조건을 적용하는 것이 안전합니다.

## 2. 결과 묶음 영수증의 출처 커밋이 비고 판정 근거 필드가 빠짐

- `league.py export(public=True)`는 원장 `source.commit`을 최상위 `source_commit`으로 바꿉니다.
- 이어서 `dashboard_data.py build`는 여전히 `source.commit`을 읽어 결과 묶음의 `receipts[].source_commit`을 빈 문자열로 만듭니다.
- `judged_by`는 `via`라는 화면용 설명으로 바뀌고, 공지한 원래 `judged_by` 필드는 결과 묶음에 남지 않습니다.
- 합성 영수증의 `sealed=true`, `early_reveal=false`, 화면용 `via`는 유지됩니다. 이번 문제는 **결과 묶음으로 변환하는 경로**에 대한 것입니다. 원래 제출 영수증의 판정 시각이 바뀌었다는 뜻은 아닙니다.

**요청:** `source_commit`은 평탄화된 값을 먼저 사용하고 이전 형식은 보조로 처리해 주세요. `judged_by`도 유지하고, 필요한 화면용 `via`를 별도로 두면 됩니다. `export → dashboard_data.bundle` 전체 경로를 회귀 시험에 넣어 주세요.

## 3. 검사 실패한 대사 파일이 화면 로더에서 다시 읽힘

- 합성 재현: 슈슈 대사 파일에 다른 팀의 가상 `pick_id`를 넣으면 대사 검사기는 올바르게 실패합니다.
- 그러나 동기화 `_apply`는 파일을 쓰고 커밋한 뒤 검사하며, `ok=false`가 나와도 그 파일을 되돌리지 않습니다.
- `load_lines`는 팀·라운드·접수 검증을 다시 하지 않고 글자 수와 가격 표현만 검사하므로, 방금 실패한 다른 팀 대사를 읽습니다.
- 실제 배포 워크플로가 검사 실패 뒤 중단되어 원격 반영을 막는지는 안전 사본만으로 확인할 수 없습니다. 확인된 것은 **반입 코드의 작업 폴더에 실패 파일이 남고 화면용 로더가 이를 읽는다는 점**입니다.

**요청:** 대사 파일은 임시 위치에서 검사한 뒤 통과한 파일만 확정 경로에 반입하거나, 실패 시 그 파일만 이전 버전으로 복원해 주세요. 이미 접수된 CSV 영수증까지 되돌릴 필요는 없습니다. 화면 로더에서도 파일의 팀·라운드·accepted 범위를 확인하면 방어가 겹쳐집니다. 기존 정상 대사를 잘못된 대사 파일이 덮어쓰지 못하는 시험도 권합니다.

1. 휴장 표시 `open: false`가 들어간 공통 자료와 해시 파일의 바이트 보존.

6. 대문자 SHA-256과 CRLF 지문이 committed → accepted(sealed)로 처리됨.
